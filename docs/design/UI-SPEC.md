## 1. 目的、范围与规则优先级

让后续规格、技术方案和实现能够还原此前认可的视觉风格与页面组织，不依赖本地被忽略的预览文件，也不靠开发者重新猜测配色、间距、交互和状态。覆盖移动 App、只读分享页、Kiranism 后台及插件扩展的共同视觉规则；v6 草稿的具体画面主要覆盖移动端。

本文件承接既有 PRD，不增加群聊、订阅、语音空间、多租户或行业业务。对于草稿未画出的注册 / 安全 / 治理 / 后台 / 插件页面，第 6 节以已有需求补齐结构和状态说明，不假称已经存在逐页视觉稿。

优先级：当前 PRD 的范围、业务状态、权限 / 数据规则优先；本规格与 UX-07 / 08 描述设计意图；token 保留草稿数值；历史 JS 仅演示入口。设计资料冲突时先遵守业务与无障碍要求，修正并记录设计差异，不让旧草稿覆盖新决策。

本轮由编制者作出的补全选择已明确标为“编制补全”：状态表达、高风险表单组织、未画页面的信息层级与原生适配原则。它们不改变流程资格、数据范围、保留时间或首版功能；组件库、导航实现、系统字体映射、精确原生尺寸和自动化工具留技术方案记录。

## 2. 视觉风格

### 开发定位与复检口径（2026-10-17用户批准）

同一原型入口按页面/状态/主题直接定位，不创建彼此分叉的HTML副本。例：
`prototype/index.html?page=login&scene=正常&theme=light`；登录、注册、验证码、账号安全、恢复分别为
`login/register/otp/security/recovery`，状态名来自选择器，theme为light/dark，font=large用于专项。
原`?account=login`兼容。开发者先实际打开对应画面，再读本页必要结构、token及组件路径。
旧UI不是设计依据；账号r2五页及选择器全部状态、浅深主题已于2026-10-17由用户原生卡片明确批准，按页面登记中的版本与摘要实现。“基础组件”独立预览页已按用户确认移除，已批准共享组件仍保留。

App忠实还原已批准设计，允许系统字体、安全区、键盘、触控与无障碍适配；明显布局/层级/颜色偏离、缺内容、遮挡
和交互问题必须修复。细微字形、抗锯齿或不影响设计意图的间距/换行差异作为建议，不单独阻塞阶段。
不设跨平台逐像素相等要求，不用微小差异反复重开整批复检；实质设计变化交用户决定。
调研依据与适用边界见[原型开发调研](../engineering/prototype-development-research-2026-10-17.md)。

### 2.1 风格描述与使用边界

整体为安静、简洁、内容优先的原生社交界面：以白 / 近黑和中性灰搭建层级，用低饱和紫色作为少量强调；留白、细线、字号 / 字重和对齐共同组织信息。Linear 提供简洁和一致性的方向，X App 提供列表、菜单、社交关系和空状态的结构参考，保留本项目配色，不复制其品牌和截图中的额外功能。

具体表现：

- 页面顶栏全宽，标题居中、两侧操作平衡；主体随原生安全区与键盘适配。
- 信息流、用户、通知、草稿等优先使用分隔线列表，避免给每一行套厚阴影卡片。
- 圆角集中在搜索、输入、媒体、引用、气泡、按钮和底部面板；头像为圆形。
- 常规操作用细描边图标，侧栏、设置和菜单同时给出文字；拥挤操作区纯图标仍有读屏名称和状态。
- 主要按钮多用前景 / 背景反相；紫色用于 AI 标识、标签、选中 / 收藏 / 点赞及小徽点，避免整屏高饱和装饰。
- 阴影只辅助浮动按钮、面板等临时层；虚拟手机外壳的圆角 / 阴影、桌面画板和伪系统栏不属于生产 UI。

### 2.3 字体与文字层级

草稿字体栈为 Arial、Microsoft YaHei UI、Microsoft YaHei、sans-serif；正式移动端使用适用系统中文字体与动态缩放。草稿 CSS px 是比较比例的参考，不直接换算为所有设备固定字号。

| 用途 | 草稿参考 | 规则 / 来源选择器 |
|---|---|---|
| 页面标题 | 19，700 字重 | 居中，`.native-title`；窄画板存在 17–18 的覆盖，生产优先保留可读性 |
| 主页名字 / 空状态标题 | 23，600–650 字重 | `.profile-name` / `.native-empty h3` |
| AI 欢迎标题 | 23，600 字重 | 行高 1.45，`.ai-welcome h1` |
| 信息流正文 | 14，行高 1.75 | `.body-copy`，以阅读为主 |
| 帖子详情正文 / 发布输入 | 16，行高 1.8 / 1.85 | `.detail-text` / `.compose-field textarea` |
| 评论 / 私信正文 | 13，行高 1.8 | `.comment-text` / `.message-bubble` |
| AI 正文 | 14，行高 1.9 | `.assistant-prose` |
| 次级信息 | 常见 11–12 | 用户名、摘要、时间等按阅读重要性适配 |
| 弱元数据 | 草稿有 9–10 | 非生产最小字号承诺；必要文字不可因此难读 |

正文左对齐、以自然换行展示，重要长文本不为了匹配截图强行截断；列表摘要可省略但详情能完整阅读。长昵称、长标题、三层回复、大字号与窄屏都要保持结构和操作可达，不能使用标题溢出遮盖返回 / 操作按钮。

### 2.5 动效与层级

侧栏约 200 ms 从左进入，面板 / 页面约 180 ms，遮罩约 120–160 ms，使用 ease-out。这些为参考节奏，不是性能验收阈值；支持减少动态效果后取消非必要动画。状态变化优先清晰反馈，不用动画伪装请求成功。

顶栏与底部导航、可滚动内容、发布浮钮、模态层 / 侧栏 / 底部面板、提示按顺序组织；一个模态流程有明确返回 / 关闭，关闭后恢复来源页与必要输入，焦点不落到遮罩后方。草稿 CSS 的 z-index 数字属于演示实现，正式组件按原生层级系统处理。

## 3. 共用组件、状态与交互

| 组件 | 结构与视觉 | 状态 / 交互要求 |
|---|---|---|
| 页面顶栏 | 返回 / 头像、居中标题、右侧动作 | 长标题与大字保持操作可达，离开编辑页按草稿规则保留输入 |
| Tab / 分段栏 | 同宽或自然宽标签；选中加深并有短下划线 | 状态不只靠颜色；切换不越权加载数据，按业务保持筛选资格 |
| 行与卡片 | 列表用细线，媒体 / 引用用轻边框圆角 | 整行 / 局部操作的点击范围明确，不让嵌套按钮误触 |
| 主 / 次按钮 | 前景反相 / 轻边框 | 正常、按下、不可用、进行中、失败可重试；进行中避免重复操作 |
| 搜索与输入 | surface 背景、圆角、弱提示 | 焦点、输入、空结果、错误；输入不因失败丢失，键盘避让 |
| 头像 / 姓名 / 标记 | 圆头像、姓名主文字、用户名次级 | 真实认证须有授权来源；占位头像不冒充真实图片加载成功 |
| 关系操作 | 关注实心、已关注描边 / 次文字 | 待审批与已关注不同状态；取消 / 移除 / 拉黑按 SOC 规则显示 |
| 徽点 / 计数 | 小强调点或 accent-soft 背景 | 去重、未读 / 已读区别由业务确定；不能以小点替代必要状态文本 |
| 底部面板 | 标题、按组分隔的图标＋文字选项 | 查看 / 编辑 / 反馈 / 屏蔽 / 拉黑 / 举报按对象资格出现，危险操作确认 |
| 提示 / 空状态 | 一句结果或标题＋解释＋适用行动 | 只有事实成功才能显示成功；无权限和不可用不泄露私人拒绝原因 |
| 来源与不可用块 | 小图标、文字、轻边框 | 点击时重验权限；失权后正文 / 媒体 / AI 依赖退出，仅留合适占位 |

编制补全的统一状态表：

| 状态 | 画面与行动 | 权限 / 数据约束 |
|---|---|---|
| 加载 | 骨架 / 进度与必要取消；首次加载不假填真实内容 | 不显示尚未获准正文，旧有效内容按业务规则判断能否保留 |
| 有内容 | 主次层级、操作、列表继续加载 | 当前授权；不以“曾显示过”保证继续可读 |
| 空 | 简洁标题、原因范围与合适行动 | 真实空数据与筛选无结果分别表达，不伪造推荐 / 计数 |
| 提交中 | 对象级进度 / 结果确认，避免重复点发 | 响应丢失先查最终状态，按既有幂等规则重试 |
| 网络 / 服务失败 | 可理解原因、重试 / 保留输入 / 受控退出 | 审核失败不自动通过，AI 失败不虚构回答或改用未批模型 |
| 权限不足 / 失权 | 合适不可用占位或登录 / 合法流程入口 | 不展示旧摘要 / 附件 / 私人拒绝原因；不自动扩大资格 |
| 删除 / 过期 / 封禁 | 当前状态、合法恢复 / 申诉入口 | 已删除、已撤权或已结束流程不因 UI 返回或刷新复活 |
| 插件停用 / 不兼容 | 不可用说明、适用更新 / 替代去向 | 有权历史可受控只读，不能安全展示则占位；兼容功能继续 |
| 校验失败 | 字段附近提示并给修正方式 | 明确服务端最终结果，客户端检查不等于正式成功 |

所有页面均套用适用状态；草稿只画出了部分状态，第 6 节标记覆盖差异。动效 / 颜色不替代文字、焦点、读屏名称、按钮状态或真实结果。

## 4. 信息架构与移动主导航

五个主入口为首页、发现、AI、私信、我的；通知从页头进入，管理个人内容从头像侧栏进入。页面条目可以由原生页面、弹层或菜单承载，语义和可达性不因实现形式变化。

| 主入口 | 顶栏与主体 | 关键动作 |
|---|---|---|
| 首页 | 左头像、社区标题、右通知；推荐 / 关注 / 最新；帖子列表 | 详情、评论、转发 / 引用、点赞、收藏、分享、发布 |
| 发现 | 左头像、发现标题、搜索 / 通知；话题、推荐用户、人工精选 | 搜索帖子 / 用户 / 话题、查看话题与用户；仅当前可见结果 |
| AI | 左头像、AI 标题、右历史 / 新建；欢迎或会话；底部输入卡 | 模型选择、扩展展示、提问、来源跳转、历史管理 |
| 私信 | 左头像、私信标题、全部 / 未读与新建；独立请求入口、会话列表 | 找人发信、当前资格提示、唯一正常会话、独立请求处理 |
| 我的 | 左头像、个人主页标题、内容搜索 / 操作；封面、资料、关系数、内容分栏 | 编辑 / 分享资料、帖子 / 回复 / 转发 / 媒体；管理内容不堆入该页 |

侧栏信息顺序：账号 / 身份 → 关注与粉丝 → 个人主页、云端草稿、收藏、最近删除、关注请求 → 底部设置与隐私。设置分类包括账号与手机号、关注审批、AI 用途、网页收录、内容偏好、屏蔽 / 拉黑、私信 / 回执、通知 / 推送；不因设置行展示而新增账号权限或后台管理资格。

## 5. 重点流程与画面

- 内容阅读：列表 → 详情 / 串 → 评论；详情放作者、正文、媒体、时间、互动与嵌套评论，底部回复输入常驻并避让键盘。回复不通过缩进无限变窄，最多三层的显示沿用 CMT，受限信息与附件同步退出。
- 发布 / 引用 / 编辑：返回、发布动作 → 大文本输入和附件 → 可见范围 / 回复范围 → 附件 / 投票 / 链接 / AI 用途及收录入口。上传、提交、待审核和正式公开分别表达；编辑审核保持最后通过版本，旧草稿不能产生新的即时公开规则。
- 关注 / 粉丝 / 审批：同一关系页分关注、粉丝、请求；用户行与状态操作相邻。关注请求和私信请求独立，期限、接受 / 拒绝 / 移除 / 冷却按既有规则，不用图标按钮推断同意。
- 私信：全部 / 未读筛选、新建选人、普通会话和请求预览分别显示。待处理请求只发初始消息，接受前不混入正常历史；S21 场景中新的合法直接消息进入唯一正常会话，旧请求仍独立，显式接受才合入同一聊天。
- AI：模型与扩展在输入区，历史 / 新建在右上。当前仅文字能力与已批准只读工具，附件 / 语音 / 外联网只展示待启用 / 不可用入口；回答显示来源和合法操作，失权时撤回相关内容。
- 个人内容：收藏、草稿、最近删除从侧栏进入；空状态保留相应行动。打开 / 恢复 / 编辑均执行当前资格，不在个人主页公开私密内容。
- 内容反馈：对象菜单按查看 / 个人管理 / 反馈与关系 / 举报分组；自己的帖子可编辑 / 删除，他人的帖子可不感兴趣 / 屏蔽 / 拉黑 / 举报 / 查看可见互动。每项当前资格依 PRD，不借菜单混入未确认评论功能。

## 7. 原生、分享网页与后台适配

移动端必须实现 Expo / React Native + Expo UI 的原生布局；CSS 和 HTML 作为设计参考，不复制为 WebView 产品或当 iOS / Android 验收结果。适配系统栏、安全区、键盘、滚动、返回、焦点和减少动效；后台 Kiranism 与分享网页保留共同语义颜色 / 层级，使用各端合适的信息密度与控件。

编制补全：网页按可读宽度自适应，正文、作者、媒体 / 引用和不可用块形成自然阅读流；后台按角色使用菜单、列表 / 表格、详情、表单、预览和审计记录组织复杂任务。手机画板的固定高度、侧栏百分比、伪系统栏及桌面页签控制不直接移植到这些端。

插件使用平台提供的主题 token、字体 / 图标原则、组件状态与插槽约定，界面反馈与当前授权同步。新插件不能引入独立“假成功”风格、遮盖核心设置、放宽数据访问或让旧端出现不可运行控件。

## 8. 设计验收与云端证据

### 8.0 当前页面绑定与批准边界

页面和状态的轻量绑定见 [`page-registry.json`](page-registry.json)。登记项必须指向真实设计来源、生产入口和实际组件路径，
并记录具体设计版本、人的批准状态及阶段整页视觉/交互复检要求。CI 只检查结构、来源、路径和版本匹配；不能证明美观、
真实交互或人的同意。账号原型 r2 五页及选择器全部状态、浅深主题已于2026-10-17获用户原生卡片明确批准；基础组件批准仍不能代替其他整页批准。Kiranism 官方模板基准
由用户指令批准，但这不批准任何后台业务页面或功能。设计未改变的实现修复可以沿用匹配批准，设计版本变化须重新批准。

App 生产 UI 只有在对应具体页面、状态和原型版本获人明确批准后才具备实现资格；完成还须在实际客户端按正常字体 1.0、
同页同状态同主题、适用视口和真实安全区完成整页对照与交互复检。后台直接以完整 Kiranism 模板为基准，免重画同款 HTML，
但新增或修改 UI 仍须在实际后台检查。未批准页面或缺少整页实际复检不能勾选完成。

设计资料完整性与实现验收是两个层面。此轮核对档案可读、CSS / JS 来源完整、token 与源规则一致、页面 / 状态映射存在；不将文档静态检查记录为 Actions 产品测试通过。

实施时的 AC-35 / AC-52 / AC-55 通过 CI-01–08 在 GitHub Actions 云端执行：

1. 以本规格、归档画面和 token 检查实际移动原生、后台、分享及插件页面的颜色语义、层级、间距、图标、对齐、截断、遮挡与状态。
2. 覆盖适用浅 / 深主题、窄屏、大字号、键盘、长昵称 / 长文本、空 / 错误 / 失权 / 加载；触控和读屏另有实际执行结果，不能只看截图。
3. 对每个覆盖场景关联页面 / 状态、PRD / AC、提交、版本、设备 / 视口、主题、Actions run、截图 / 差异和交互结果。
4. 设计适配差异有说明与记录；实际页面未运行、必需状态缺失、视觉错位、按钮失效或缺证据不能标通过。
5. 视觉差异阈值、云端设备 / 浏览器组合、存储期限及自动化实现由方案核验；不预先捏造固定像素容差或云端测试已完成。

AC-55 记录 UI 资料与原生适配的一致性；各业务 AC 仍验证真实权限和流程，设计一致不替代业务通过。
