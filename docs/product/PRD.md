全文使用以下状态，各种状态不能混同：

| 标记 | 含义 | 后续处理 |

| 已确认 | 用户已明确要求的功能、约束或规则 | 进入首版规格与验收，除非后续明确变更 |

### 0.2 术语

| 术语 | 本文含义 |
|---|---|
| 普通 / 长帖 | 单条内容；长帖提供更长正文、分段及展开全文，使用统一内容体系 |
| 评论 / 嵌套回复 | 原帖下的讨论内容，保留父评论与被回复对象关系；业务上与作者顺序续写的帖子串区分 |
| 转发 | 保留原帖关联，不附加新的引用正文；不复制一份永久可访问的原帖 |
| 引用 | 用户附加文字并关联原帖；整条引用的有效可见范围不得超过原帖 |
| 帖子串（Thread） | 同一作者按顺序关联的多条帖子；不是评论树，也不是多人协作文章 |
| 关注者 | 当前存在有效的“该用户关注作者”关系的账号；待批准请求不是有效关注 |
| 屏蔽（Mute） | 本人的内容过滤偏好，不改变对方资源的真实访问权限 |
| 拉黑（Block） | 双方关注解除、新互动受阻、双方内容互相隐藏的账号关系 |
| 删除 | 立即停止业务访问；用户主动删除与管理员处置分别记录，最终物理清理由数据策略执行 |
| 撤权 | 某用户失去对资源的访问资格；不等于删除仍供其他合法用户访问的资源 |
| AI 检索 / 总结 / 推荐 | 三项独立的作者使用许可；普通关键词搜索不等于 AI 检索 |
| 只读分享网页 | 用于阅读、登录以取得阅读授权及打开 App，不提供完整社区交互 |
| 请求结束 | 对发送者的统一展示状态，不揭示接收者拒绝、删除或忽略等具体行为 |

## 1. 产品定位、目标与约束

### 1.1 产品定位与场景

面向所有普通用户的综合社交社区。用户在空闲时间浏览自己关心的内容，分享想法、经历、媒体或问题，通过点赞、评论、转发、引用、关注和私信建立联系。AI 是社区核心功能之一，帮助用户查找真实帖子、理解讨论、发现话题和获取有来源的回答。

主要场景：

1. 新用户通过邀请与手机号验证加入，完善个人资料，选择兴趣并发现可关注的用户。
2. 用户保存草稿、发布单帖或帖子串，获得互动并能编辑、调整权限、删除或恢复内容。
3. 用户切换推荐、关注和最新信息流，通过搜索、话题和用户主页进入讨论。
4. 用户发起评论或投票、转发或引用内容，并在明确的权限范围内继续交流。
5. 陌生人提出一次私信请求，接收者决定是否建立会话；任一方可管理通知、回执、屏蔽和拉黑。
6. 用户向 AI 提问或主动选择一条内容进行分析，通过真实来源核实结论；无结果或服务异常时能够理解原因并恢复。
7. 运营人员处理举报、审核内容、执行授权范围内的处罚和独立申诉复核，查看必要的运营与 AI 服务指标。

### 1.2 首版目标

首版用户能完成手机号注册登录、资料完善、多类型发布、三类信息流浏览、搜索发现、评论与投票、转发引用、关注审批、一对一私信、AI 社区问答和会话管理。运营人员能通过后台管理用户、内容、媒体、话题、举报、处罚、申诉及 AI 配置。

正确性、权限和隐私是硬性门槛。激活、互动、留存、AI 使用与质量、成本和稳定性先建立真实基线，不虚构增长或预先承诺未确认的经营指标。

### 1.3 首版范围

| 模块 | 首版交付 |
|---|---|
| 身份 | 手机 OTP、邀请制内测、会话管理、手机号更换、受控账号恢复、退出和注销 |
| 社交 | 个人主页、关注 / 取消关注、审批、关注 / 粉丝名单、移除粉丝、屏蔽与拉黑 |
| 内容 | 普通文本、简化长帖、图片 / 多图、视频、GIF、链接预览、投票、转发、引用、帖子串 |
| 讨论 | 三层评论与回复、图片或 GIF 附件、点赞、编辑删除、评论范围和排序 |
| 个人内容 | 私密收藏、云端与本地草稿、编辑历史、作者审核状态、最近删除与恢复 |
| 发现 | 推荐 / 关注 / 最新、帖子 / 用户 / 话题搜索、筛选、联想、搜索历史、热门与推荐用户 |
| 私信 | 一对一会话、文本 / Emoji / 图片 / GIF / 链接、独立请求箱、未读、免打扰、删除、回执与输入提示 |

### 1.4 首版不做与延期

- 不做广告、会员订阅、付费内容、打赏、付费私信、虚拟货币、支付、退款、分账。
- 不做独立复杂 Articles 编辑器、专业富文本排版、文章目录；问答、活动等只保留统一内容模型扩展空间。
- 不做群聊、语音 / 视频通话、直播、语音空间、通讯录导入、X Lists、批量关注等未经确认的截图功能。
- 不做多人共同续写、协作编辑和跨帖子串合并。
- 不做“为所有人撤回私信”、公开在线状态、最后活跃时间和具体投票者名单。
- 不做 AI 自动发帖、评论、点赞、关注、私信、修改账号或后台写操作。
- AI 实时外部搜索、图片 / 文件解析、语音、图片生成等真实能力不属于已确认首版交付；仅展示待确认入口。
- 官方认证申请、核验、授予、撤销和认证筛选完整流程后续再做；不提供付费认证。
- 第三方登录、高级 / 地点搜索、指定社区 / 群组可见和复杂机器学习推荐后续评估。

## 2. 技术与复用边界

**TECH-01** 移动端固定基于 Expo / React Native 与 Expo UI 开发，面向 iOS / Android；优先复用官方原生组件和成熟生态能力。**TECH-02** 后端固定 Supabase，优先利用 Auth、Postgres、Storage、Realtime 与 Functions 等已具备的能力。**TECH-03** 后台固定 Kiranism / Next.js / shadcn/ui 二次开发，须替换或适配示例认证、数据和业务权限。

**TECH-04** 产品不以更换上述技术栈解决困难。依赖稳定版本、版本锁定、升级与兼容测试由 Spec Kit 方案明确；不沿用未经核对的旧版本号。组件、短信、推送、审核、搜索与 AI 服务可以在此边界内评估复用和配置接口；额外基础设施必须说明所解决的缺口、费用、维护和数据流向。

官方文档核验与方案约束（核验日 2026-10-13）：

| 依据 | 能确认的技术事实 | 本产品仍须完成的核验 |
|---|---|---|
| [Expo UI](https://docs.expo.dev/versions/latest/sdk/ui/) | 提供 SwiftUI / Jetpack Compose 原生 UI 接入 | 实际组件覆盖、跨平台布局、键盘、长列表、无障碍与原生推送构建 |
| [Kiranism 官方仓库](https://github.com/Kiranism/next-shadcn-dashboard-starter) | 是 Next.js / shadcn/ui 后台模板 | Supabase 身份接入、角色授权和真实业务；模板示例不构成已实现社区功能 |
| [Supabase Phone sign-in](https://supabase.com/docs/guides/auth/phone-login) | 手机 OTP 需要短信服务配置 | 目标市场服务商、发送 Hook / 适配方式、签名模板、限流、费用与可靠性 |
| [Supabase MFA](https://supabase.com/docs/guides/auth/auth-mfa) | 提供额外认证因子和认证等级信息 | 本产品管理员 MFA 在 API / 数据层强制执行、高风险再次验证与恢复 |
| [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) | 可按当前用户实施行级访问控制；高权限角色可绕过 RLS | 表、视图、函数、检索、实时事件与后台入口均要验证，不能仅打开 RLS 就宣称安全 |
| [Storage 下载](https://supabase.com/docs/guides/storage/serving/downloads)、[Smart CDN](https://supabase.com/docs/guides/storage/cdn/smart-cdn) | 私有对象可经鉴权或限时签名访问；签名不因 Auth 密钥变化自动失效，CDN 缓存与 URL 过期不是同一控制 | 按部署方案验证撤权和缓存行为；敏感对象逐次鉴权，见第 15 节 |

本节是已确认技术选型的事实核验，不是数据库设计、供应商选定或兼容性验证完成证明。数据模型、接口、部署拓扑、组件清单和构建版本留给正式方案，但必须满足本文产品规则。

## 3. 角色、页面与访问范围

### 3.1 角色

| 角色 | 能力与限制 |
|---|---|
| 访客 | 阅读有效公开内容和公开统计；不能互动、查看具体关系 / 互动者名单或使用个性化 AI |
| 普通登录用户 | 按当前内容权限、社交关系、接收设置和账号状态使用功能；拥有自己的草稿、收藏与 AI 会话 |
| 内容作者 | 编辑、调整自己内容的可见范围及 AI 限制、控制评论、管理审核与删除记录；不能编辑他人的回复 |
| 关注审批接收者 / 私信请求接收者 | 处理各自独立的请求；任何一种接受都不能自动授予另一种关系 |
| 被功能限制 / 临时封禁 / 永久封禁用户 | 按处罚范围受到约束，保留必要的原因与申诉入口，不获得敏感资源访问豁免 |
| 管理员 | 按第 14 节明确角色和操作权限，普通用户登录不能自动获得后台权力 |
| AI/MCP | 当前用户请求的只读工具调用代理；不是超级管理员，不持有跨用户读取授权 |

## 5. 主页、关系、屏蔽与拉黑

来源：S03、S05、S06、S08、S11。

### 5.1 个人资料与用户名

**PRF-01** 主页包含头像、昵称、唯一用户名、简介、可选背景图、注册时间和关注 / 粉丝数，支持编辑；内容分类包含帖子、回复、媒体，保留草图中的转发分类。所在地为视觉稿中的可选示例字段，尚未作为必须填写项确认。

**PRF-02** 个人资料与已发布内容分别授权。主页不公开本人的收藏、私人草稿或 AI 会话。作者能在本人内容管理中查看待审核、未通过、限制展示、已编辑和删除状态；普通访客不能借“我的列表”读取这些内容。

**PRF-03** 唯一用户名与显示名称分开，修改须检查格式、唯一性和保留词。修改频率与旧名占用冷却暂定各 30 天。链接资源和历史提及绑定稳定账号 ID；改名不造成链接指向后来抢注旧名的用户，历史提及显示当前名称。

### 5.2 关注与审批

| ID | 规则 |
|---|---|
| SOC-01 | 默认立即关注；开启“需要批准关注请求”后，仅批准的新请求成为有效关注；关注与粉丝数按有效关系计算，不含待处理请求。 |
| SOC-02 | 开启审批保留已有粉丝；关闭审批只改变后续新增关注，原待处理请求由用户自行处理，不批量自动批准。 |
| SOC-03 | 接收者在独立关注请求列表批准、拒绝或删除；发送者可取消请求；同一账号对同一接收者最多一个待处理请求。反复 / 批量或疑似骚扰额外限流，严重或重复滥用可暂定延长冷却至 30 天或执行账号处罚；服务端限流及冷却不可由重复点击 / 多端绕过。 |
| SOC-04 | 对发送者统一展示请求结束，不区分接收者拒绝或删除。拒绝 / 删除后暂定 30 天冷却，主动取消或自然过期后暂定 7 天冷却；关注请求有效期尚待确认。 |
| SOC-05 | 取消关注或移除粉丝后，立即失去由该关系授予的受限内容资格；公开内容仍公开。移除粉丝无需先拉黑，不自动解除其他合法权限。 |
| SOC-06 | 无审批时，被移除用户可能重新关注；启用审批则重新申请；要阻止再次关注或互动须拉黑。拉黑后请求持续受阻，解除后仍需满足当前规则和有效冷却。 |
| SOC-07 | 游客只能看公开主页的关系数量，不能开具体名单。登录者可看有权访问的公开账号名单；审批账号名单限本人及获准的关注者。名单 API 同步执行权限、账号状态、拉黑校验。 |
| SOC-08 | 关注审批不自动把公开帖子改成受限，也不自动批准私信请求；接受私信请求不能自动授予关注或私有内容权限。 |

### 5.3 屏蔽与拉黑

| 场景 | 内容屏蔽（Mute） | 账号拉黑（Block） |
|---|---|---|
| 关注关系 | 保留 | 双方有效关注解除；解除拉黑不自动恢复 |
| 默认信息流 / 推荐 | 账号屏蔽完全过滤本人默认内容；关键词 / 话题过滤匹配内容 | 双方内容互相隐藏，不因排序变化重新出现 |
| 搜索 | 默认隐藏；主动选择显示屏蔽内容后，可展示仍有权查看的结果 | 双方不能借搜索绕过关系限制 |
| 普通通知 | 过滤被屏蔽账号的普通 / 推荐通知；安全通知不受抑制 | 不再通过通知暴露对方内容或允许新的互动 |
| 发帖 / 评论 / 提及 / 转发 / 引用 | 不直接改变双方写权限 | 双方新互动受阻；服务端判断，不只隐藏按钮 |
| 私信 | 会话免打扰独立；账号屏蔽不等于断开会话 | 既有历史只读，不能继续发送 |
| 已有公共互动 | 不自行删除 | 点赞、转发、引用等合法记录不自动删除；双方隐藏具体记录，其他有权者仍可见，聚合计数原则保留 |
| AI | 主动推荐 / 热门 / 总结遵循过滤；明确找已知内容时，仍可经授权查找 | 检索、引用和推荐不能绕过拉黑关系 |

**SOC-09** 拉黑保护系统能识别的账号访问与互动，不承诺公开内容对同一自然人绝对不可见。不用侵入性设备追踪保证退出登录或更换账号后不可阅读公开内容；受限内容始终执行资源授权。

**SOC-10** 屏蔽方不向被屏蔽方发送屏蔽通知。账号屏蔽、关键词 / 话题屏蔽、会话免打扰、拉黑、移除粉丝是独立操作，设置说明须体现效果差异。

## 6. 内容、发布、草稿与帖子串

来源：S02、S03、S05、S06、S07、S08。

### 6.1 类型与组合

| 内容形态 | 首版支持 | 组合与边界 |
|---|---|---|
| 普通文本 | 纯文本、Emoji、标签、提及、普通链接 | 正文长度见暂定参数；不能把长帖当成多个自动分割帖子 |
| 简化长帖 | 更长连续正文、分段、折叠与展开全文 | 同一条内容，同样支持互动和授权；无复杂独立文章编辑器 |
| 图片 | 文字 + 单图 / 多图、替代文本 | 不在一帖中混合图片与视频 / GIF；数量和大小可配置 |
| 视频 | 文字 + 一个视频，预览 / 播放 | 不与多图混排；大小、时长与允许格式需验证 |
| GIF | 文字 + 动态附件 | 按动态媒体处理，与图 / 视频不混排 |
| 链接 | 正文链接、有限预览 | 标题、摘要、缩略图、来源域名；预览数上限待确认，失败保留正文链接 |
| 投票 | 问题、单选选项、可选说明、截止时间 | 不与图片 / 视频 / GIF 混合；结果和编辑见第 7 节 |
| 转发 | 与原内容稳定关联 | 不复制可永久展示的正文，不能扩大原内容授权 |
| 引用 | 附加文字 + 原内容关联预览 | 原帖不可用时整条引用含附加文字停止展示；引用附加媒体组合待确认 |
| 帖子串 | 作者按顺序连续创建 / 续写 | 每条遵循相应类型组合；整串统一权限、批次原子发布 |

**POST-01** 采用统一内容与关联体系，表示作者、类型、正文、附件、标签、提及、原帖引用、串顺序、状态、当前权限、编辑标记和有效互动。具体数据库拆表与评论实现方式由方案设计，不在 PRD 虚构为已完成。

**POST-02** 标签可进入话题检索和讨论；提及绑定账号 ID。链接抓取必须处理无效、重复、恶意、超时和加载失败；服务端防 SSRF 等不可信输入风险。内部受限帖子的外链 / 引用预览不能公开泄露正文或缩略图。

### 6.2 发布闭环与状态

**POST-03** 用户编辑时保留文本、选定附件和元数据。发布状态明确区分：草稿 → 上传中 → 待提交 → 发布中 → 结果确认 / 成功或失败待重试；内容审核状态独立，提交成功可能进入待审核，而非一定已公开。

**POST-04** 每次逻辑提交使用唯一标识并服务端幂等。响应丢失或超时而结果不确定时，先查询最终结果；不能直接重新创建第二条帖子。重复点击、重连和强制关闭不产生重复帖子、评论、私信或计数。

**POST-05** 上传失败保留成功附件和正文，只重试失败文件；提交失败不清空输入。区分网络、身份 / 权限、文件类型、大小、审核 / 服务端错误；分别提供重试、修改输入、重新登录或保存草稿入口。

**POST-06** 媒体在正式发布与审核许可前仅暂存，不公开未完成内容。失败批次可复用上传结果，孤立暂存对象有清理机制；清理不得删除仍被有效草稿 / 已发布内容使用的对象。

### 6.3 草稿

**DRF-01** 登录用户文字草稿与元数据保存于 Supabase，并同步本人多个设备；编辑中的本地临时保存用于断网恢复。访客草稿仅在当前设备，登录后由本人选择导入，不静默传入账号。

**DRF-02** 多端编辑发生冲突时提示选择 / 恢复，不静默覆盖较新版本。上传状态和可复用附件由方案明确；不承诺不同设备可以访问仅存在本机的未上传文件。

**DRF-03** 草稿仅本人及明确授权的系统流程访问，不进公开搜索、推荐、热门或默认 AI。主动选择本人草稿交给 AI 的边界见第 12 节。注销按数据清理规则处理。

### 6.4 帖子串

**THR-01** 只有原作者续写，其他人用评论、转发与引用参与；保留连续顺序和完整串跳转，每条独立保存编辑与互动记录。

**THR-02** 一次创建 / 续写提交中的各条记录与关系准备完成后统一可见；初始整串原子发布，续写批次不得对外出现只成功了前几条的半成品。上传任一步失败保留草稿，不泄露暂存附件。

**THR-03** 创建与后续整体修改采用统一可见范围；串内不能单独扩大一条的权限。收紧立即阻止新的业务访问，放宽至公开须提醒并确认整串及符合发布规则的附件将开放。外部副本不能可靠收回。

**THR-04** 删除首帖时整串退出公开展示、搜索、推荐与 AI；删除中间帖保留必要的顺序占位，不公开其正文 / 媒体，不删除其他人的合法内容或错误串联后续帖子。整串恢复与依赖规则见第 9、21 节。

| POL-07 | 结束后向参与者发站内通知，手机推送服从设置；处置、原帖失效或权限丧失后结果 / 通知 / 直接 API 同样受限。 |

进行中作者未投票时是否有统计例外未作额外确认，本文不提供例外；不得以后台管理接口作为作者前台权限。注销投票者去身份聚合及违规票处理必须分别记录，不能因用户暂不可见就任意改票。

| CMT-04 | 默认一级评论最新倒序，可切热门；回复内部时间正序。热门考虑有效点赞、回复与时间衰减，排序不暴露失权、屏蔽、拉黑或已删除内容。 |

| CMT-06 | 关闭评论保留合法既有评论，不清空讨论；重新开放或改变范围后，服务端立即按当前条件判定新回复。 |
| CMT-07 | 自己评论可编辑正文与附件替代文本，不替换已发布媒体；显示已编辑，保留必要治理历史，普通用户不浏览完整旧版本。普通链接不生成独立富媒体卡片。 |
| CMT-08 | 首版不提供单独评论收藏；评论转发 / 引用等未确认能力不因概念稿按钮而新增。原帖删除时整棵讨论退出正常访问，不能经评论链接、搜索或附件重新读取。 |

## 9. 编辑、可见性、删除与恢复

来源：S02、S05、S06、S08、S11、S12。

### 9.1 编辑与版本

**EDIT-01** 正常帖子发布后允许编辑正文、标签和图片替代文本，即使已收到互动；不替换已发布媒体，不改变原引用关系。长帖遵循同一规则，投票语义遵循 POL-02。

**EDIT-02** 保存编辑记录并展示“已编辑”。作者可查看本人帖子的历史版本，普通用户不能默认浏览全部旧版本；具有授权的内容审核员可为具体治理查看历史，记录敏感访问审计。旧版仍受当前权限、账号、内容和删除状态约束。

**EDIT-03** 待审核编辑重新进入审核队列；已被限制展示的内容不能因编辑绕过复核。已公开内容的新版本等待审核或审核未通过时，继续展示上一个通过审核的版本；未经必要审核的新版本不先对外展示。作者可在管理入口查看新版本与真实审核状态，通过后才统一切换；发生独立违规限制时仍可隐藏整条内容。对应普通帖子、评论、引用文字和投票允许编辑的说明采用一致策略；审核决定须绑定被审核版本，不能因先前版本通过而自动公开后来未审版本。此规则已于本次审阅后确认，见 Q-12 与 S12。

### 9.2 当前访问规则

**VIS-01** 支持公开、仅关注者可见、仅自己可见。读取 / 展示权限由当前身份、资源有效性、账号与审核状态、拉黑关系、可见范围及关联依赖共同决定；互动权限再叠加登录状态、处罚、评论范围或私信设置。

**VIS-02** 推荐、普通搜索、AI/MCP、网页、通知、媒体、版本和缓存的输出都不得扩大授权。正文、摘要、缩略图、标签、关联引用者附加文字和结果卡片同样是内容，不可仅保护详情正文。

**VIS-03** 转发 / 引用仅允许当前有权查看且允许互动的用户创建；有效可见范围为自身设置与原帖当前授权的交集。原帖或链上的任一依赖不可见时，不能通过后续再引用公开泄露源内容。

不同关联不能被实现为同一种级联删除或读取条件：

| 关联 | 当前访问约束 |
|---|---|
| 评论 / 子回复 | 全部依赖原帖当前可读；中间评论删除或对当前用户隐藏时，只隐藏该节点及不可展示的被回复预览，不自动删除其他作者的合法回复。不能借预览重述已删除正文。 |
| 转发 / 引用 / 再引用 | 沿原内容依赖链取权限交集；任一必要来源不可用时，该引用附加文字也不可展示。 |
| 帖子串 | 整串统一可见性并依赖有效首帖；中间条目独立删除保留顺序占位，不影响其他有效条目的原顺序。 |
| 媒体 / 派生文件 / 旧版本 | 跟随当前所属资源及关联依赖；本人草稿、作者内容管理、最近删除与具体治理证据使用各自受控管理入口，不授予普通浏览资格。 |
| 通知 / 搜索摘要 / AI 来源 | 当前可访问资格先于缓存、排序或旧记录；已有记录不能成为授权来源。 |

| 原内容变化 | 原帖与评论 | 转发 / 引用 | AI / 搜索 / 通知 / 媒体 |
|---|---|---|---|
| 收紧权限、失去关注资格或被拉黑 | 对无权者停止展示；既有合法记录可保留 | 整条引用含附加文字隐藏；通用不可用提示，不泄露拒绝的具体原因 | 后续访问重新校验，隐藏依赖输出，清理索引 / 缓存，不沿用旧快照 |
| 作者主动删除 | 正文与媒体立即不可读，讨论从正常入口移除 | 保留“原帖已删除，引用内容不可用”等最小占位；无权确认删除状态者仍用通用提示 | 停止输出、屏蔽依赖 AI 回答、进入恢复或清理流程 |
| 管理员限制 / 删除 | 执行独立处置，普通恢复不解禁 | 不展示被限制正文或附加引用文本 | 不进入普通检索 / 热门 / AI，可按明确治理授权保留证据 |
| 恢复或重新放宽 | 再验当前规则与依赖，不自动恢复所有状态 | 能否展示取决于当前原帖和引用本身有效性 | 重新确认资格后重建，不能恢复仍被其他规则禁止的内容 |

### 9.3 最近删除与清理

**DEL-01** 用户主动删除帖子 / 评论立即停止正常展示，暂定提供 10 秒撤销提示与 30 天最近删除恢复窗口。恢复不是绕过审核、拉黑、原帖或帖子串状态的通行证。

**DEL-02** 删除中间评论 / 串帖子不删除他人内容；首帖删除导致整串不可用。恢复期内恢复首帖时，一并恢复当次连带隐藏且仍有效的条目；独立删除或被限制的条目继续按自身状态处理，不自动复活。作者恢复子项不能使仍被删除的原帖或首帖自动可读；用户真实删除与因依赖失效暂不可读分别记录。恢复窗口按实际用户删除时间计算，依赖隐藏不重新启动已存在的独立删除期限。恢复前统一校验当前权限、审核、媒体与其他依赖。范围选择已于本次审阅后确认，见 Q-05 与 S12。

**DEL-03** 管理员违规删除 / 依法限制不通过普通最近删除恢复，走复核 / 申诉。到期永久清理后不提供普通恢复；法定或争议证据独立授权保留，不能继续被业务检索使用。

**DEL-04** “立即不可访问”与“后台物理清理”分开：恢复期内为恢复目的保留的对象必须受保护，不提前删除需要恢复的唯一副本；到期清理实际对象、引用与索引。严撤权访问 / 普通媒体残余窗口见第 15 节，不能把后台清理未完成当成继续访问理由。

## 10. 互动、收藏、信息流与发现

## 11. 一对一私信与独立请求箱

来源：S03、S05、S06、S08。

### 11.1 接收范围与会话资格

**DM-01** 正常会话支持文本、Emoji、图片、GIF 和链接，包含会话列表、全部 / 未读筛选、查找用户发起私信、消息时间、实时收发、未读同步、免打扰、举报与拉黑。首版不做群聊、语音 / 视频通话和为所有人撤回。

**DM-02** 接收设置包含允许范围及关闭全部私信。有效关注者能否直接发起会话由接收方设置决定；陌生人须进入请求箱。本文中的“关注者”指发送者当前关注接收者，不把反向关注或待审批请求视为资格。接收设置各项默认值待确认，不能以参考 App 的默认值替代。仅已认证用户的接收范围留作后续认证能力，不在首版伪造认证资格。

**DM-03** 已接受的正常会话不因关闭陌生人请求、取消关注或开启关注审批而自动终止；任一方拉黑、关闭全部私信或系统安全限制后停止新消息。每次发送再次检查双方身份、会话状态、接收范围、拉黑与处罚。

**DM-04** 已接受的私信会话不授予关注者可见帖子、名单或其他资源的阅读权限；批准关注也不自动接受一个已有私信请求。查找接收者、发送请求和接受请求分别授权。

### 11.2 陌生人请求状态

| 状态 / 操作 | 接收者体验 | 发送者体验与服务端规则 |
|---|---|---|
| 不满足接收设置或被拉黑 | 不建立请求或会话 | 不允许提交；只提示当前不能联系，不泄露对方具体隐私设置 |
| 初始请求提交 | 独立请求箱中一条待处理消息 | 每对账号最多一条待处理请求；只能一条文本 / Emoji，不允许图片、GIF 或链接 |
| 等待处理 | 可以阅读请求、接受、拒绝、删除、举报或拉黑 | 不能追加消息、重复创建或借修改请求反复提醒 |
| 接受 | 进入正常会话 | 初始请求保留为会话起始消息；后续可按当前资格发送正常媒体 |
| 拒绝 / 删除 | 从待处理列表移除；保留必要举报 / 反骚扰入口 | 统一“请求已结束”，不揭示具体操作；暂定结束后 30 天不能重新申请 |
| 自然过期 | 暂定创建后 30 天自动退出请求列表 | 同样展示结束，暂定过期后再冷却 30 天；过期与冷却是两个期限 |
| 拉黑 | 既有正常历史只读，停止联系 | 冷却到期也不能再次请求；解除后重新按当前关系、设置和有效冷却判断 |

**DM-05** 以上转换由服务端保证，处理过期、接受与重复请求的并发竞争；过期后不能接受旧请求。发信限流、请求限额、账号风险和关系冷却分别执行，不能通过多端、重装、重复点击绕过。

**DM-06** 接收设置改变时，不将待处理请求自动转为正常会话。处理与发送均重新校验当前状态和拉黑关系。关闭全部私信时，是否允许继续接受旧请求是未决交互；在确认前不允许该操作恢复新消息权限，见 Q-06。

### 11.3 发送结果、未读与删除

**DM-07** 发送状态区分本地待发送、发送中、服务端已保存、接收端已送达、已读、失败和结果待确认。系统推送被接受不代表对方设备已收到，更不代表对方已读。断网保留输入；结果不确定先按提交标识查证，重试不能产生重复消息或未读计数。

**DM-08** 消息、请求与未读状态保存在服务端；实时连接断开后重连同步，不仅依赖瞬时事件或操作系统推送。多端阅读后的未读最终一致，历史分页与实时到达不能重复显示。会话免打扰只影响提醒，不阻止消息存储或同步。

**DM-09** 删除单条消息暂定仅对操作方隐藏，另一方仍可看已收到的消息；不等同于双方撤回或服务器永久删除。删除整个会话只移除本人的列表项，对方历史不变；再次收到合法新消息时重新出现，原历史仍可见。删除会话不解除拉黑、不接受请求、不重开结束状态。

**DM-10** 已读回执和正在输入提示可分别关闭；不展示公开在线状态或最后活跃时间。输入信号短暂、不长期储存。关闭回执不影响本人未读管理；是否采用双方均开启才显示的策略属于用户建议，待确认或采用明确标记的编制建议，见 Q-06、D-02。

**DM-11** 私信附件按敏感媒体逐请求鉴权，只有当前合法参与者或具体举报证据的授权审核人员可读。发送者注销后的身份脱敏、接收方保留与期限均遵循第 16 节；后台没有任意浏览全部私信的入口。

## 12. AI 助手、MCP 与作者使用控制

来源：S03、S05、S06、S07、S08、S09。

### 12.1 功能、输入与工具边界

| ID | 已确认要求 |
|---|---|
| AI-01 | AI 为首版核心模块，支持社区内容查找、社区事实问答、帖子 / 讨论总结、相关内容推荐、热门话题发现和社区帮助问答。安全通用问题可简要回答，区分一般知识、社区证据与无法确认。 |

| AI-06 | 社区事实结论提供可点击、真实且支持该结论的来源，附必要作者 / 时间 / 内容标识；点击再次鉴权。无相关证据、工具失败、权限不足、来源失效分别反馈，不编造帖子、投票数据、规则或引用。 |

模型可替换不等于自动把数据传往另一家服务商。发生故障或高成本保护时，只有已告知且批准的处理范围内才能调整；不能未经明确政策自动转发给另一家第三方。

### 12.2 内容能否进入 AI

| 内容 | 泛社区问答 / 热门 / 自动推荐 | 主动选中分析 |
|---|---|---|
| 已发布、有效公开帖子 | 对应 AI 用途许可、当前阅读权限及过滤规则全部允许时可用 | 同样检查作者许可与当前状态 |
| 关注者可见帖子 | 不进入广泛社区总结、热门回答或面向多人的推荐；不无差别批量传输 | 用户主动选择且当前有权、作者允许相应用途、发送前知晓必要正文会给已批准模型时可用 |
| 仅自己可见帖子 | 不进入公共 AI 检索库 | 仅所有者主动选择并确认分析；继续检查本人作者设置 |
| 私人草稿 | 不自动检索，不自动加入上下文 | 仅本人主动选择自己的草稿，明确告知并确认必要处理 |
| 私信、举报证据、管理员记录 | 不作普通社区问答来源 | 首版没有通用选取入口；不能以“主动提问”取得系统任意读取权限 |
| 待审核 / 限制展示 / 已删除内容、旧版本 | 不经普通 AI 暴露 | 作者管理和治理资格不等于 AI 分析许可；首版不借此绕过限制 |
| 未能识别来源的手动粘贴文字 | 视为用户主动提交输入，不授予原帖访问权 | 发送前告知第三方处理；无法保证识别全部原作者、完整来源链和逐项设置 |

**AI-08** 对内部链接、可识别社区引用和已明确关联原帖的内容，必须执行原帖权限与作者设置；不能将已经识别的受限内容改称“手动粘贴”后绕过。对无法识别来源的输入，不主动扩展读取受限原帖、相关附件或私人信息。

**AI-09** 只发送完成当前请求所需的最小正文与来源信息，不附带手机号、认证凭据、无关个人资料或整库数据。允许请求处理与允许模型训练分别约定；用户请求分析不能被解释为训练同意。服务商的处理区域、训练用途、保留、删除能力、安全与合同条件均待实际核验。

### 12.3 账户与逐帖设置

**AI-10** 账户分别控制 AI 检索、AI 总结、AI 推荐；单帖可进一步关闭其中某项。有效许可取账户设置与逐帖限制的交集；账户关闭时单帖不能重新开启。公开内容按明确告知的社区 AI 规则默认可以参与，默认文案与同意呈现须确认，不把公开等同于已同意一切第三方处理。

**AI-11** 按实际用途执行对应许可。允许检索而禁止总结时，可以返回合规检索链接，不能借“搜索回答”生成该帖摘要；一个流程实际包含检索、总结或推荐多个用途时，应满足所涉及的全部许可，不能更换功能名称绕过限制。用途对应的具体实现与评估用例须在规格中细化。

**AI-12** 关闭某项用途适用于该账号 / 帖子的后续调用和受影响历史，停止对应上下文构建、索引和缓存使用。普通关键词搜索与社区阅读继续按原可见性运行。重新开启后重新核验内容当前有效性和用途资格，逐步恢复索引，不复活已删除或被其他规则限制的内容。

### 12.4 历史回答撤回与继续对话

**AI-13** 回答须保留足以执行撤权的来源关联，包括直接内容与依赖此前回答引入的来源。原帖删除、失去阅读资格、被拉黑、审核限制或作者撤回有关 AI 用途后，相关原文、摘要、引用和实质依赖它的回答停止展示及继续作为上下文使用。

**AI-14** 有可靠来源追踪时，可重新生成不依赖撤回来源的回答；不能可靠区分受影响部分时，隐藏整条受影响回答并标记不可用。不能只移除来源链接仍保留原回答，也不能让下一轮从隐藏回答“记忆”中重述。未受影响的本人输入与合法回答可保留。

**AI-15** 打开历史、复制、继续提问、重试和来源跳转都执行当前校验；权限变化事件用于及时刷新，但安全不能仅依赖事件成功送达。离线不能展示无法重新核验的受限内容及依赖它的回答。已看过、截图、复制到系统外的回答以及系统无法控制的第三方副本无法保证收回。

### 12.5 会话管理、额度与恢复

**AI-16** 支持新建、查看历史、打开旧会话、自动简短标题、修改标题、删除会话、停止生成、复制合法回答、失败重试及基本反馈。历史与标题仅本人可访问；删除立即从 UI 和正常检索移除，物理清理见第 16 节。会话标题也不能保留已失权内容的敏感摘要。

**AI-17** 保存请求状态并区分提交中、检索中、生成中、已完成、已停止、失败和结果待确认。超时 / 断网保留输入和已合法保存历史，不把半截回答标成完成；重试沿用可追踪请求关联，避免重复气泡、重复额度和重复计费账目。服务商是否已收费无法确定时记录并对账，不直接判为免费失败。

**AI-18** 封闭内测免费使用 AI；暂定每用户每日 20 次成功完成请求，最大输入 8,000 Token（含检索上下文）、最大生成 2,000 Token。重置时区由部署配置，数值均非已批准生产承诺。失败 / 可安全重试不重复扣用户额度；服务商实际成本独立记录，停止生成可能已发生的成本不能抹除。

**AI-19** 支持单用户请求 / 成本保护、单次预算、全局每日成本上限和高成本调用保护，并由获授权管理员配置。并发请求不能突破额度或多次扣同一成功请求。用户额度耗尽、模型限流或全局预算保护时明确说明原因及可知的恢复时间，保留输入；可展示普通授权搜索作为恢复入口。

**AI-20** AI 故障不阻断普通社区浏览、发布、互动和私信。后台支持模型 / 服务商 / MCP 配置、工具启停、错误、延迟、Token 和实际 / 待对账成本统计；原始对话访问需另行授权与审计，不因 AI 运维角色默认开放。

## 14. 治理、处罚、申诉与后台

来源：S03、S04、S05、S07、S08。

### 14.1 内容审核与举报

**GOV-01** 基础发布检查与发布后巡检结合。通过必要检查的正常内容可发布；待进一步确认的进入待审核或限制展示。作者可查看、编辑、撤回 / 删除待审核内容及允许公开的处理说明。待审核内容不进公共信息流、搜索、热门、推荐或普通 AI。

**GOV-02** 举报帖子、评论、账号、私信；保存举报对象、理由、必要证据与提交结果。状态至少有待处理、审核中、已处理、不予处理；用户能查看允许披露的进度和反馈，不暴露举报人身份、其他人的证据或内部敏感处理信息。

**GOV-03** 举报多不等于违规。审核员基于证据可提醒、限制传播、删除内容、限制账号功能或封禁，并记录原因、操作人、时间、对象、必要依据与结果；涉及高影响自动处罚时可人工复核。紧急先限制传播也须留记录与复核。

**GOV-04** 基础垃圾内容、骚扰、重复违规、异常互动、重复发布与协同刷量防护。可配置限流与风险阈值，但不能跳过授权或用运营伪造计数。举报提交与受理故障分别展示，避免提交失败却显示已受理。

### 14.2 处罚与恢复

| 处罚类型 | 新操作 | 既有合法内容 | 用户与治理入口 |
|---|---|---|---|
| 功能限制 | 仅停止决定中列明的功能 | 原则继续展示；独立内容处置仍生效 | 显示原因、受限功能、开始 / 结束时间和申诉 |
| 临时封禁 | 指定期间禁止发布和互动 | 原则可以合法阅读，但从推荐 / 热门暂移除 | 受限入口可读处罚、期限与申诉状态 |
| 永久封禁 | 禁止发布和互动 | 从正常信息流 / 搜索 / 推荐移除；主页 / 直接链接为适当占位 | 保留必要处罚说明、申诉及独立证据授权 |

**GOV-05** 账号处罚、单条内容处置和用户主动删除分别记录；一次账号处罚不能证明所有帖子违规，也不自动永久删除所有文件。到期或撤销只恢复该处罚实际影响、尚有效的状态，再检查当前权限、拉黑、原帖、审核和媒体依赖。

**GOV-06** 不恢复用户主动删除内容、已过期请求或主动取消的关注，不自动解除拉黑；申诉恢复不是全部关系回滚。记录恢复决定和执行结果，有失败重试，避免显示账号已恢复而对应资源错误暴露或长期被错误隐藏。

**GOV-07** 受影响用户可提交理由与必要材料并查看申诉状态。不同于原处置人的有权人员最终复核，原处置人可补充说明但不能独自决定。没有第二名合格复核者时进入待复核，不以自审代替；审核人只访问该案所需证据。

### 14.3 后台角色与操作范围

| 角色 | 可执行范围 | 不因角色自动获得的权限 |
|---|---|---|
| 超级管理员 | 管理管理员、授权与撤销、邀请资格、全局安全和系统配置；高风险操作再次验证 | 无理由浏览所有私信、草稿、AI 对话或跳过证据授权 |
| 内容审核员 | 处理举报、帖子 / 评论 / 投票 / 媒体审核、违规记录、授权范围内的警告和封禁、必要历史版本 | 数据库凭据、全局安全配置、无关私人会话 |
| 社区运营员 | 话题、公告、置顶 / 精选 / 推荐位及汇总运营指标 | 私信、私人草稿、完整 AI 对话及默认处罚权 |
| AI 运维员 | 经授权的服务商 / 模型 / MCP 配置，调用故障、延迟、Token 与成本 | 默认内容处置权、完整私人输入输出、其他用户资源 |
| 审计只读员 | 已授权审计记录和系统事件 | 修改、删除、处罚和任意用户正文 |

**ADM-01** 后台包括运营总览、用户搜索与管理、封禁 / 解封、帖子 / 评论 / 投票管理、媒体管理、举报 / 审核 / 申诉队列、话题 / 公告 / 推荐位、违规记录、角色权限、审计与系统配置。对应真实数据，不以 Kiranism 示例页面当交付。

**ADM-02** 权限按角色、具体操作及资源分别授予，后端每次验证；能打开页面不等于能执行页面上的全部操作。未经授权导出、敏感数据读取或配置变更必须拒绝；没有确认的业务导出场景不默认开放全库导出。

**ADM-03** 管理员手机号 OTP + 额外 MFA，优先评估 TOTP；只有 OTP 不能执行后台高权限操作。封禁、敏感查看、导出、角色 / 密钥配置等高风险操作按风险再次验证并填写原因。权限撤销、过期和退出后的后续敏感操作拒绝，不仅前端关闭按钮。

**ADM-04** 首位超级管理员由部署负责人在受保护一次性初始化中建立，完成后关闭入口；后续由有权人员邀请 / 创建并授权。普通注册不能成为管理员。账号权限与 MFA 的服务端强制程度由方案验证。

**ADM-05** MFA 丢失不只靠短信恢复全权限；依靠可信部署 / 服务端访问、归属核验、一次性恢复凭据和审计。多人时优先另一超级管理员复核；仅一人时采用受控紧急恢复，不公开可滥用的接口。恢复后撤销旧会话 / 凭据并通知。

**ADM-06** 敏感操作和必要敏感读取写服务端审计：操作人、时间、对象、动作、理由、结果及可追踪请求关联。日志访问受控，避免记录凭据、完整对话和不必要个人内容；普通修改接口不能任意篡改审计。

**ADM-07** 管理员原则上不任意阅读私信。只有具体举报或必要安全事件，按授权访问相关最小证据并审计；运营、AI 运维与审计角色不能借统计或日志越权读取。证据、业务原文和物理保留独立授权。

## 15. 媒体、缓存、离线与撤权

来源：S06、S07、S08。

### 15.1 访问分级

| 等级 | 范围与策略 | 撤权与验证 |
|---|---|---|
| 普通公开帖子附件 | 同样优先私有 Storage Bucket；先校验当前内容有效性再提供地址 | 支持删除 / 收紧后的控制；公开历史签名与缓存残余窗口须实测，不能默认永久 URL |

**MEDIA-01** 媒体、缩略图、GIF、视频分片、预览与下载均继承所属内容及关联依赖授权。外部对象地址不应成为绕过 Supabase RLS 的入口；高权限凭据只在可信服务端受控使用，不进入客户端包。

**MEDIA-02** 签名有效期、CDN 缓存 TTL、应用缓存与会话令牌是不同控制；Auth 密钥轮换不能当即时撤销文件签名保证。验证旧链接、缓存命中、重连、离线、多端、账号退出 / 注销、权限收紧、被拉黑和关系变化后的实际表现，记录最坏残余窗口。

**MEDIA-03** 离线不展示无法重新确认权限的他人受限帖子、媒体及依赖回答，曾经有权不授予永久离线授权。本人的未发布本地草稿按草稿规则保留；退出时清理应用管理的受限缓存、URL 与会话关联，不把草稿恢复与失权内容访问混为一谈。

**MEDIA-04** 永久删除同步清理实际对象、关联记录、派生文件、索引和应用管理缓存；单用户撤权不删除其他合法用户需要的共同对象。删除恢复期和具体证据保留不维持普通业务可读。已下载、截图或外部另存无法可靠收回，须与系统可控撤权明确区分。

### 15.2 发布校验与播放

**MEDIA-05** 服务端校验文件类型、真实格式、大小、时长、归属和必要审核；UI 选择通过不是服务端认可。未知 / 不支持格式、安全检查失败、超限和处理超时保留草稿并给具体恢复方式。首版复杂视频转码不擅自扩大，但必须满足已批准格式的播放；格式清单和兼容方案由技术核验。

**MEDIA-06** 视频默认仅 Wi-Fi 静音自动播放、蜂窝点击；提供始终、仅 Wi-Fi、从不自动播放及关闭预加载设置。GIF 在可视区可播放，尊重减少动态效果及省流量；离开可视区暂停或合理降耗，用户可主动开启视频声音。

## 16. 数据保留、删除与恢复机制

来源：S05、S07、S08。下表所有时间均为**暂定候选值**，需结合最终市场、争议处理和实际备份能力确认；表中的立即业务限制是已确认规则，不能等保留期满才隐藏。

| 数据分类 | 立即业务效果 | 暂定物理保留 / 清理期限 |
|---|---|---|
| 注销账号资料 / 认证关联 | 禁止登录，停止关联内容正常展示、移除个人索引 / 关系 | 主数据 30 天内删除或不可逆匿名化 |
| 注销作者帖子 / 评论 / 媒体 | 不再正常可读；只保留不泄露身份 / 原文的必要结构占位 | 30 天内删除 / 匿名化，独立有依据证据除外 |
| 注销用户备份 | 不允许经恢复重现已生效删除数据 | 目标 90 天内轮转清除；恢复必须重新应用删除记录 |
| 已送达接收者的私信 | 发送方注销后显示已注销，无身份链接；接收方按合法会话可保留 | 最后会话活动后 24 个月过期清理；本人隐藏 / 列表移除与永久删除区分 |
| 用户主动删除帖子 / 评论 | 正常内容及附件访问停止；可撤销 / 最近删除管理 | 10 秒撤销、30 天恢复期；到期永久清理，不提前毁掉唯一恢复副本 |
| 主动删除 AI 会话 | UI、检索和上下文立即移除 | 30 天内清理会话、可重建索引及缓存 |
| 未主动删除 AI 会话 | 本人可读，来源仍按当前权限校验 | 连续 12 个月无活动进入过期清理流程，提前说明实际策略 |
| AI 调用元数据日志 | 只记录模型、时间、耗时、Token、费用、错误与必要请求关联 | 30 天，不默认完整提示词 / 回答 |
| 必要受控 AI 原始调试输入输出 | 明确启用、敏感字段限制、独立访问审计 | 最长 7 天 |
| 举报证据 | 仅具体案件授权使用，不进普通业务 / AI / 搜索 | 结案后 180 天，有理由 / 授权才可延期 |
| 管理员审计 | 限制访问，避免不必要原文 | 1 年 |
| OTP / 认证安全日志 | 最小反滥用记录，不记录可使用验证码或秘密 | 30 天 |

**DATA-01** 业务数据库、Storage、派生媒体、AI 会话、全文 / 向量索引、缓存、日志与备份分别有清理责任和可查状态。删除 / 匿名化失败可追踪重试，不能只从 UI 消失就声称数据全部删除。

**DATA-02** 依法或为有效争议确需保留的最小证据独立授权、明确理由 / 期限 / 责任人，不以审计为由无限保留所有个人信息。异常延期、恢复与清理形成审计；不能把保留副本重新接回普通业务输出。

**DATA-03** 同一资源兼具恢复目的、案件证据或多个会话参与者的合法保留需求时，按各自授权分别管理；用户个人视图删除不等于删除他人的合法记录。私信“本人提前删除”的物理含义尚待确认，见 Q-06，不能擅自扩大为替双方删除。

**DATA-04** 备份恢复后，先重放删除 / 撤权 / 处罚及有效隐私设置，再开放业务读取；验证备份不会复活注销账号、被删内容或已撤回 AI 来源。RPO / RTO、备份周期和可行轮转期限由部署方案提出，产品确认后验收。
