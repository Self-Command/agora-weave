## 0. 阅读规则与需求效力

本文汇总产品负责人已经给出的需求和后续修正。业务规则以最新明确决策为准；网页概念稿和参考截图用于表达布局，不能新增、删除或覆盖业务要求。

全文使用以下状态，各种状态不能混同：

| 标记 | 含义 | 后续处理 |
|---|---|---|
| 已确认 | 用户已明确要求的功能、约束或规则 | 进入首版规格与验收，除非后续明确变更 |
| 已确认默认值 | 用户已采用的初始数值或策略，须纳入统一配置中心 | 可在授权、有效范围和变更规则内调整；产品确认不等于实际部署 / 清理 / 性能已验证 |
| 暂定 | 用户给出的候选默认值、建议策略或工程基线 | 可用于估算与设计，但须完成对应验证或产品确认；不能写成上线承诺 |
| 待确认 | 尚未作出决定、存在实质歧义或依赖外部核验 | 见第 21 节；不能由视觉演示、供应商默认值或开发者猜测替代 |
| 编制建议 | 本次为补齐交付结构或协调规则提出的建议 | 单独列于第 22 节，尚未获得用户确认 |
| 后续 / 首版不做 | 明确延期或排除的能力 | 只保留扩展边界，不计入首版开发范围 |

除明确标注的暂定、待确认和编制建议外，功能规则来自已确认的用户要求。标为首版的功能必须具备持久化、服务端授权、正常与异常流程及跨入口一致性；不能以“有一个入口”代替业务完成。

| 屏蔽（Mute） | 本人的内容过滤偏好，不改变对方资源的真实访问权限 |
| 拉黑（Block） | 双方关注解除、新互动受阻、双方内容互相隐藏的账号关系 |

| 撤权 | 某用户失去对资源的访问资格；不等于删除仍供其他合法用户访问的资源 |
| AI 检索 / 总结 / 推荐 | 三项独立的作者使用许可；普通关键词搜索不等于 AI 检索 |

## 1. 产品定位、目标与约束

### 1.1 产品定位与场景

面向所有普通用户的综合社交社区。用户在空闲时间浏览自己关心的内容，分享想法、经历、媒体或问题，通过点赞、评论、转发、引用、关注和私信建立联系。AI 是社区核心功能之一，帮助用户查找真实帖子、理解讨论、发现话题和获取有来源的回答。

平台提供维护的标准和接口，支持开发者独立扩展前端、后端和管理后台，按需安装、组合和管理插件，无需为每项业务修改核心源码。项目保持通用性，不预置行业需求；校园、兴趣等只说明未来用途。未来采用何种插件组合、构建何种产品、使用单个或多个独立部署，属于使用者自主选择，当前不交付相应行业业务、多社区运营或多产品编排。

主要场景：

1. 新用户通过邀请与手机号验证加入，完善个人资料，选择兴趣并发现可关注的用户。
2. 用户保存草稿、发布单帖或帖子串，获得互动并能编辑、调整权限、删除或恢复内容。
3. 用户切换推荐、关注和最新信息流，通过搜索、话题和用户主页进入讨论。
4. 用户发起评论或投票、转发或引用内容，并在明确的权限范围内继续交流。
5. 陌生人提出一次私信请求，接收者决定是否建立会话；任一方可管理通知、回执、屏蔽和拉黑。
6. 用户向 AI 提问或主动选择一条内容进行分析，通过真实来源核实结论；无结果或服务异常时能够理解原因并恢复。
7. 运营人员处理举报、审核内容、执行授权范围内的处罚和独立申诉复核，查看必要的运营与 AI 服务指标。
8. 插件开发者依据版本化文档和模板创建扩展，在隔离环境独立调试页面、API、数据库与权限，完成打包和完整流程测试，不触达真实用户数据。
9. 平台管理员查看插件来源、兼容、依赖和权限，在指定环境安装 / 启用 / 升级 / 停用 / 卸载；系统识别实际变更类别并执行相应验证、部署与构建，展示失败、发布和恢复状态。

### 1.2 首版目标

首版用户能完成手机号注册登录、资料完善、多类型发布、三类信息流浏览、搜索发现、评论与投票、转发引用、关注审批、一对一私信、AI 社区问答和会话管理。运营人员能通过后台管理用户、内容、媒体、话题、举报、处罚、申诉及 AI 配置。

正确性、权限和隐私是硬性门槛。激活、互动、留存、AI 使用与质量、成本和稳定性先建立真实基线，不虚构增长或预先承诺未确认的经营指标。

插件平台是首版正式能力：交付可运行安装与管理、三端扩展接口、完整开发文档与工具、独立前后端隔离测试环境；与上列完整社交官方模块一并验收。首版面向项目自身及受邀开发者，经审核接入；生产用户启用前须超级管理员按具体版本 / 权限 / 范围确认（S21）。实际可用平台与业务闭环不能由接口预留或静态演示替代。

## 2. 技术与复用边界

**TECH-01** 移动端固定基于 Expo / React Native 与 Expo UI 开发，面向 iOS / Android；优先复用官方原生组件和成熟生态能力。**TECH-02** 后端固定 Supabase，采用官方 Docker Compose 在自有或自管服务器上自部署，优先中国大陆部署，不依赖 Supabase 云端托管。自行管理 Postgres、Auth、Storage、Realtime 与 Studio 等服务，按实际自部署能力复用 Functions 等组件；备份、升级、监控、秘密和访问配置由部署方案落实。Studio 是基础设施管理控制台，不替代社区运营后台。**TECH-03** 后台固定 Kiranism / Next.js / shadcn/ui 二次开发，须替换或适配示例认证、数据和业务权限。

**TECH-04** 产品不以更换上述技术栈解决困难。依赖稳定版本、版本锁定、升级与兼容测试由 Spec Kit 方案明确；不沿用未经核对的旧版本号。组件、短信、推送、审核、搜索与 AI 服务可以在此边界内评估复用和配置接口；额外基础设施必须说明所解决的缺口、费用、维护和数据流向。

**TECH-05** 按ED-22以可用业务功能为优先目标，本地开发测试为主；日常只运行目标用例和直接受影响回归，按功能批次实施／测试／审查，Actions按需复验和发布，不作为每次开发前置。首版产品及跨端功能覆盖保持，真实功能测试不能由编译或mock代替。生产仍独立部署并须具体授权。

## 6. 内容、发布、草稿与帖子串

来源：S02、S03、S05、S06、S07、S08、S13、S14。

### 6.1 类型与组合

| 内容形态 | 首版支持 | 组合与边界 |
|---|---|---|
| 普通文本 | 纯文本、Emoji、标签、提及、普通链接 | 已确认默认最多 2,000 字符；统一配置，不把长帖当成多个自动分割帖子 |
| 简化长帖 | 更长连续正文、分段、折叠与展开全文 | 已确认默认最多 10,000 字符；同一条内容，同样支持互动和授权，无复杂独立文章编辑器 |
| 图片 | 文字 + 单图 / 多图、替代文本 | 默认最多 9 张、每张 ≤10 MB；不在一帖中混合图片与视频 / GIF；数量、大小及组合规则统一配置 |
| 视频 | 文字 + 一个视频，预览 / 播放 | 默认最多 1 个、≤200 MB 且 ≤5 分钟；不与多图混排；允许格式与实际兼容须验证 |
| GIF | 文字 + 动态附件 | 默认最多 1 个、≤15 MB；按动态媒体处理，与图 / 视频不混排 |
| 链接 | 正文多个普通链接、最多 1 个链接预览卡片 | 标题、摘要、缩略图、来源域名；预览失败 / 超时 / 目标不可访问不影响正文链接展示和复制 |
| 投票 | 问题、单选选项、可选说明、截止时间 | 不与图片 / 视频 / GIF 混合；结果和编辑见第 7 节 |
| 转发 | 与原内容稳定关联 | 不复制可永久展示的正文，不能扩大原内容授权 |
| 引用 | 仅附加文字 + 原内容关联预览 | 首版不能额外附加图片、视频或 GIF；原帖被删除 / 不可见时整条引用含附加文字停止展示，只保留不可用占位 |
| 帖子串 | 作者按顺序连续创建 / 续写 | 每条遵循相应类型组合；整串统一权限、批次原子发布 |

**POST-01** 采用统一内容与关联体系，表示作者、类型、正文、附件、标签、提及、原帖引用、串顺序、状态、当前权限、编辑标记和有效互动。具体数据库拆表与评论实现方式由方案设计，不在 PRD 虚构为已完成。

**POST-02** 标签可进入话题检索和讨论；提及绑定账号 ID。每帖最多展示 1 个链接预览卡片，正文可含多个普通链接；预览生成失败、加载超时或目标不可访问不影响正文链接展示和复制。链接抓取必须处理无效、重复、恶意、超时和加载失败；服务端防 SSRF 等不可信输入风险。内部受限帖子的外链 / 引用预览不能公开泄露正文或缩略图。

### 6.2 发布闭环与状态

**POST-03** 用户编辑时保留文本、选定附件和元数据。发布状态明确区分：草稿 → 上传中 → 待提交 → 发布中 → 结果确认 / 成功或失败待重试；内容审核状态独立，提交成功可能进入待审核，而非一定已公开。

**POST-04** 每次逻辑提交使用唯一标识并服务端幂等。响应丢失或超时而结果不确定时，先查询最终结果；不能直接重新创建第二条帖子。重复点击、重连和强制关闭不产生重复帖子、评论、私信或计数。

**POST-05** 上传失败保留成功附件和正文，只重试失败文件；提交失败不清空输入。区分网络、身份 / 权限、文件类型、大小、审核 / 服务端错误；分别提供重试、修改输入、重新登录或保存草稿入口。

**POST-06** 媒体在正式发布与审核许可前仅暂存，不公开未完成内容。失败批次可复用上传结果，孤立暂存对象有清理机制；清理不得删除仍被有效草稿 / 已发布内容使用的对象。

### 6.3 草稿

**DRF-01** 登录用户文字草稿与元数据保存于 Supabase，并同步本人多个设备；编辑中的本地临时保存用于断网恢复。访客草稿仅在当前设备，登录后由本人选择导入，不静默传入账号。

**DRF-02** 多端编辑发生冲突时提示选择 / 恢复，不静默覆盖较新版本。上传状态和可复用附件由方案明确；不承诺不同设备可以访问仅存在本机的未上传文件。

**DRF-03** 草稿仅本人及明确授权的系统流程访问，不进公开搜索、推荐、热门或默认 AI。主动选择本人草稿交给 AI 的边界见第 12 节。注销按数据清理规则处理。

### 6.4 帖子串

**THR-01** 只有原作者续写，其他人用评论、转发与引用参与；保留连续顺序和完整串跳转，每条独立保存编辑与互动记录。

**THR-02** 一次创建 / 续写提交中的各条记录与关系准备完成，并全部满足必要审核与当前发布资格后，才对有权读者统一可见；提交成功或仅部分条目审核通过不等于整批已公开。初始整串原子发布，续写批次不得对外出现只成功了前几条的半成品；某条仍待审核 / 未通过时整批不先公开，作者在管理入口查看真实状态，既有有效串不因新续写批次等待而自动隐藏。上传任一步失败保留草稿，不泄露暂存附件。

**THR-03** 创建与后续整体修改采用统一可见范围；串内不能单独扩大一条的权限。收紧立即阻止新的业务访问，放宽至公开须提醒并确认整串及符合发布规则的附件将开放。外部副本不能可靠收回。

**THR-04** 删除首帖时整串退出公开展示、搜索、推荐与 AI；删除中间帖保留必要的顺序占位，不公开其正文 / 媒体，不删除其他人的合法内容或错误串联后续帖子。整串恢复与依赖规则见第 9、21 节。

| CMT-08 | 首版不提供单独评论收藏；评论转发 / 引用等未确认能力不因概念稿按钮而新增。原帖删除时整棵讨论退出正常访问，不能经评论链接、搜索或附件重新读取。 |

## 9. 编辑、可见性、删除与恢复

来源：S02、S05、S06、S08、S11、S12、S14。

### 9.1 编辑与版本

**EDIT-01** 正常帖子发布后允许编辑正文、标签和图片替代文本，即使已收到互动；不替换已发布媒体，不改变原引用关系。长帖遵循同一规则，投票语义遵循 POL-02。

**EDIT-02** 保存编辑记录并展示“已编辑”。作者可查看本人帖子的历史版本，普通用户不能默认浏览全部旧版本；具有授权的内容审核员可为具体治理查看历史，记录敏感访问审计。旧版仍受当前权限、账号、内容和删除状态约束。

**EDIT-03** 待审核编辑重新进入审核队列；已被限制展示的内容不能因编辑绕过复核。已公开内容的新版本等待审核或审核未通过时，继续展示上一个通过审核的版本；未经必要审核的新版本不先对外展示。作者可在管理入口查看新版本与真实审核状态，通过后才统一切换；发生独立违规限制时仍可隐藏整条内容。对应普通帖子、评论、引用文字和投票允许编辑的说明采用一致策略；审核决定须绑定被审核版本，不能因先前版本通过而自动公开后来未审版本。此规则已于本次审阅后确认，见 Q-12 与 S12。

### 9.2 当前访问规则

**VIS-01** 支持公开、仅关注者可见、仅自己可见。读取 / 展示权限由当前身份、资源有效性、账号与审核状态、拉黑关系、可见范围及关联依赖共同决定；互动权限再叠加登录状态、处罚、评论范围或私信设置。

**VIS-02** 推荐、普通搜索、AI/MCP、网页、通知、媒体、版本和缓存的输出都不得扩大授权。正文、摘要、缩略图、标签、关联引用者附加文字和结果卡片同样是内容，不可仅保护详情正文。

**VIS-03** 转发 / 引用仅允许当前有权查看且允许互动的用户创建；有效可见范围为自身设置与原帖当前授权的交集。原帖或链上的任一依赖不可见时，不能通过后续再引用公开泄露源内容。

不同关联不能被实现为同一种级联删除或读取条件：

| 关联 | 当前访问约束 |
|---|---|
| 评论 / 子回复 | 全部依赖原帖当前可读；中间评论删除或对当前用户隐藏时，只隐藏该节点及不可展示的被回复预览，不自动删除其他作者的合法回复。不能借预览重述已删除正文。 |

| 媒体 / 派生文件 / 旧版本 | 跟随当前所属资源及关联依赖；本人草稿、作者内容管理、最近删除与具体治理证据使用各自受控管理入口，不授予普通浏览资格。 |
| 通知 / 搜索摘要 / AI 来源 | 当前可访问资格先于缓存、排序或旧记录；已有记录不能成为授权来源。 |

### 9.3 最近删除与清理

**DEL-01** 用户主动删除帖子 / 评论立即停止正常展示，已确认默认提供 10 秒撤销提示与删除后 30 天最近删除恢复窗口；时长、恢复期限和受控生效策略由配置中心管理。恢复重新校验当前权限、审核、拉黑及依赖，不能绕过管理员处罚、原帖或帖子串状态。

**DEL-02** 删除中间评论 / 串帖子不删除他人内容；首帖删除导致整串不可用。恢复期内恢复首帖时，一并恢复当次连带隐藏且仍有效的条目；独立删除或被限制的条目继续按自身状态处理，不自动复活。作者恢复子项不能使仍被删除的原帖或首帖自动可读；用户真实删除与因依赖失效暂不可读分别记录。恢复窗口按实际用户删除时间计算，依赖隐藏不重新启动已存在的独立删除期限。恢复前统一校验当前权限、审核、媒体与其他依赖。范围选择已于本次审阅后确认，见 Q-05 与 S12。

**DEL-03** 管理员违规删除 / 依法限制不通过普通最近删除恢复，走复核 / 申诉。到期永久清理后不提供普通恢复；法定或争议证据独立授权保留，不能继续被业务检索使用。

**DEL-04** “立即不可访问”与“后台物理清理”分开：恢复期内为恢复目的保留的对象必须受保护，不提前删除需要恢复的唯一副本；到期清理实际对象、引用与索引。系统可控的新访问撤权即拒绝，普通媒体同样适用，见第 15 节；不能把后台清理未完成当成继续访问理由。

## 11. 一对一私信与独立请求箱

来源：S03、S05、S06、S08、S13、S14、S21。

### 11.1 接收范围与会话资格

**DM-01** 正常会话支持文本、Emoji、图片、GIF 和链接，包含会话列表、全部 / 未读筛选、查找用户发起私信、消息时间、实时收发、未读同步、免打扰、举报与拉黑。首版不做群聊、语音 / 视频通话和为所有人撤回。

**DM-02** 默认允许有效关注者直接发送私信，陌生人可发送一条私信请求。接收方可关闭陌生人请求、调整接收范围或关闭全部私信，拉黑关系始终优先。本文中的“关注者”指发送者当前关注接收者，不把反向关注或待审批请求视为资格；未开启关注审批时，陌生人成功关注后即取得关注者资格，可依当前接收设置直接发私信。仅已认证用户的接收范围留作后续认证能力，不在首版伪造认证资格。

**DM-03** 通过显式接受请求或合法直接发信建立的正常会话，不因关闭陌生人请求、取消关注或开启关注审批而自动终止；任一方拉黑、关闭全部私信或系统安全限制后停止新消息。每次发送再次检查双方身份、会话状态、接收范围、拉黑与处罚。

**DM-04** 正常私信会话不授予关注者可见帖子、名单或其他资源的阅读权限；批准关注也不自动接受一个已有私信请求。查找接收者、发送请求和接受请求分别授权；待处理请求与后来合法直接发信建立的会话并存时按 DM-12 处理。

### 11.2 陌生人请求状态

| 状态 / 操作 | 接收者体验 | 发送者体验与服务端规则 |
|---|---|---|
| 不满足接收设置或被拉黑 | 不建立请求或会话 | 不允许提交；只提示当前不能联系，不泄露对方具体隐私设置 |
| 初始请求提交 | 独立请求箱中一条待处理消息 | 每对账号最多一条待处理请求；只能一条文本 / Emoji，不允许图片、GIF 或链接 |
| 等待处理 | 可以阅读请求、接受、拒绝、删除、举报或拉黑 | 不能追加到请求、重复创建或借修改请求反复提醒；后来取得直接发信资格的新消息按 DM-12 进入正常会话 |
| 接受 | 进入或并入同一正常会话 | 初始请求保留为原始消息；已有正常会话时不另建第二个聊天，后续可按当前资格发送正常媒体 |
| 拒绝 / 删除 | 从待处理列表移除；保留必要举报 / 反骚扰入口 | 统一“请求已结束”，不揭示具体操作；默认结束后 30 天不能重新申请 |
| 自然过期 | 默认创建后 30 天自动退出请求列表 | 同样展示结束，默认过期后再冷却 30 天；过期与冷却是两个期限 |
| 发送者主动取消 | 不再保留待处理请求，已结束不重新激活 | 统一结束状态；默认取消后冷却 7 天，不套用拒绝 / 删除 / 过期的 30 天冷却 |
| 拉黑 | 既有仍有访问资格的正常历史只读，停止联系；受拉黑阻止的旧请求不再激活 | 冷却到期也不能再次请求；解除后新请求重新按当前关系、设置和有效冷却判断，不能重新激活旧请求 |

**DM-05** 以上转换由服务端保证，处理过期、接受与重复请求的并发竞争；过期后不能接受旧请求。请求默认有效期 30 天，拒绝 / 删除 / 自然过期后冷却 30 天，主动取消后冷却 7 天，已于 S14 确认；不同结束原因、单用户请求限制和防骚扰阈值分别统一配置，与关注请求互不影响。发信限流、请求限额、账号风险和关系冷却分别执行，不能通过多端、重装、重复点击或重新申请绕过拉黑。

**DM-06** 接收设置改变时，不将待处理请求自动转为正常会话。关闭全部私信后，已有待处理请求保留至原过期时间，可查看、删除和举报，但不能接受；重新开启后仍有效的请求可正常处理，不重置有效期。已结束、已过期或已被拉黑关系阻止的请求不能重新激活；处理与发送均重新校验当前状态和拉黑关系。

**DM-12** 已有陌生人待处理请求后，发送者又取得有效关注者等当前接收设置允许的直接发信资格，其合法新消息进入同一对账号的正常会话；旧请求及初始消息继续在请求流程中独立处理，不因关注或新消息自动接受、结束或并入正常历史，也不重置原有效期。只有接收者显式接受仍有效请求后，初始消息才合入该正常会话，不产生第二个聊天或重复消息。旧请求拒绝、删除、取消或过期按原结束 / 冷却规则办理，不改变已合法建立会话的资格；正常发送仍受双方状态、拉黑、关闭全部及处罚约束。请求箱、正常会话历史、未读和提醒按实际状态分开并去重，初始消息未接受前不能由正常会话分页 / API 读取。接受 / 过期 / 新消息并发须保留单一有效结果，具体排序及已读 / 未读计数口径留规格落实既定真实状态和去重要求。来源 S21，Q-19 已确认。

### 11.3 发送结果、未读与删除

**DM-07** 发送状态区分本地待发送、发送中、服务端已保存、接收端已送达、已读、失败和结果待确认。系统推送被接受不代表对方设备已收到，更不代表对方已读。断网保留输入；结果不确定先按提交标识查证，重试不能产生重复消息或未读计数。

**DM-08** 消息、请求与未读状态保存在服务端；实时连接断开后重连同步，不仅依赖瞬时事件或操作系统推送。多端阅读后的未读最终一致，历史分页与实时到达不能重复显示。会话免打扰只影响提醒，不阻止消息存储或同步。

**DM-09** 删除单条私信立即从操作用户会话视图隐藏，并撤销其通过正常应用 / API 访问该消息及附件的权限；另一方已经收到的消息与合法访问不受影响。不能因一方删除而直接物理删除共享记录，清理遵循第 16 节。删除整个会话只移除本人的列表项，对方历史不变；再次收到合法新消息时重新出现，仍有权且未被本人单条删除的原历史可见，不能恢复已撤销的单条消息 / 附件资格。删除会话不解除拉黑、不接受请求、不重开结束状态。

**DM-10** 已读回执默认关闭；只有双方都开启时才互相显示已读，任意一方关闭后双方均不显示回执，本人未读数量和标记不受影响。已读回执和正在输入提示可分别关闭；不展示公开在线状态或最后活跃时间。输入信号短暂、不长期储存。

**DM-11** 私信附件按敏感媒体逐请求鉴权，当前合法参与者须同时拥有该条消息的访问资格；本人单条删除后不能借附件 URL、历史分页、重连或其他正常入口重新访问。具体举报证据只供案件授权审核人员按最小范围读取，不能恢复删除方的普通访问资格。发送者注销后的身份脱敏、接收方保留与期限均遵循第 16 节；后台没有任意浏览全部私信的入口。

| AI-01 | AI 为首版核心模块，支持社区内容查找、社区事实问答、帖子 / 讨论总结、相关内容推荐、热门话题发现和社区帮助问答。安全通用问题可简要回答，区分一般知识、社区证据与无法确认。 |
| AI-02 | 正式已确认输入为文字、内部帖子 / 串链接和从详情主动选择内容。外链仅作文本，不自动抓取；首版不启用外部实时互联网搜索。模型选择与扩展入口已确认展示，图片 / 文件 / 语音等真实处理能力尚待确认。 |
| AI-03 | 模型选择只能列出后台实际批准且配置成功的模型，提供当前选择及不可用状态，不展示虚构可用能力。切换模型须继续遵循当前数据处理政策与作者设置；服务商尚未选定。 |
| AI-04 | MCP 首版只读：搜索帖子、查询详情和讨论、查公开资料 / 话题 / 趋势、推荐相关内容、查经审核的社区帮助资料。不开放用户写操作、账号修改、后台管理或任意数据库 / 网络执行能力。 |
| AI-05 | 每次工具调用绑定当前请求用户，重新检查内容可见性、依赖、作者 AI 设置、账号和拉黑状态；不以创建会话时的权限快照长期授权。高权限服务凭据不能直接返回跨用户数据。 |
| AI-06 | 社区事实结论提供可点击、真实且支持该结论的来源，附必要作者 / 时间 / 内容标识；点击再次鉴权。无相关证据、工具失败、权限不足、来源失效分别反馈，不编造帖子、投票数据、规则或引用。 |
| AI-07 | 工具参数、返回量、上下文大小和调用次数有边界。帖子、帮助资料和检索结果都是待分析的数据，不能被其中的“指令”用于改变系统授权、泄露秘密或调用额外工具。 |

模型可替换不等于自动把数据传往另一家服务商。发生故障或高成本保护时，只有已告知且批准的处理范围内才能调整；不能未经明确政策自动转发给另一家第三方。

### 12.2 内容能否进入 AI

| 内容 | 泛社区问答 / 热门 / 自动推荐 | 主动选中分析 |
|---|---|---|
| 已发布、有效公开帖子 | 对应 AI 用途许可、当前阅读权限及过滤规则全部允许时可用 | 同样检查作者许可与当前状态 |
| 关注者可见帖子 | 不进入广泛社区总结、热门回答或面向多人的推荐；不无差别批量传输 | 用户主动选择且当前有权、作者允许相应用途、发送前知晓必要正文会给已批准模型时可用 |
| 仅自己可见帖子 | 不进入公共 AI 检索库 | 仅所有者主动选择并确认分析；继续检查本人作者设置 |
| 私人草稿 | 不自动检索，不自动加入上下文 | 仅本人主动选择自己的草稿，明确告知并确认必要处理 |
| 私信、举报证据、管理员记录 | 不作普通社区问答来源 | 首版没有通用选取入口；不能以“主动提问”取得系统任意读取权限 |
| 待审核 / 限制展示 / 已删除内容、旧版本 | 不经普通 AI 暴露 | 作者管理和治理资格不等于 AI 分析许可；首版不借此绕过限制 |
| 未能识别来源的手动粘贴文字 | 视为用户主动提交输入，不授予原帖访问权 | 发送前告知第三方处理；无法保证识别全部原作者、完整来源链和逐项设置 |

**AI-08** 对内部链接、可识别社区引用和已明确关联原帖的内容，必须执行原帖权限与作者设置；不能将已经识别的受限内容改称“手动粘贴”后绕过。对无法识别来源的输入，不主动扩展读取受限原帖、相关附件或私人信息。

**AI-09** 只发送完成当前请求所需的最小正文与来源信息，不附带手机号、认证凭据、无关个人资料或整库数据。第三方 AI 推理处理、日志与存储默认限定中国大陆境内，未经单独批准不能跨境传输；服务商必须明确承诺不将社区内容、用户输入及相关数据用于模型训练，并提供处理位置、保留期限、训练用途、删除能力及相关分包商的数据处理条款。具体供应商、模型与合同在接入前核验，不满足条件不能处理社区用户数据。后台只可切换已经批准且符合当前政策的服务商 / 模型，不能借配置变更自动向未经批准的境外服务商发送数据。公开、受限、私人草稿及其他数据继续按本节资格、最小必要与告知执行；列出数据政策不新增私信 / 证据的通用 AI 读取入口。

### 12.3 账户与逐帖设置

**AI-10** 账户分别控制 AI 检索、AI 总结、AI 推荐；单帖可进一步关闭其中某项。有效许可取账户设置与逐帖限制的交集；账户关闭时单帖不能重新开启。公开内容按明确告知的社区 AI 规则默认可以参与，默认文案与同意呈现须确认，不把公开等同于已同意一切第三方处理。

**AI-11** 按实际用途执行对应许可。允许检索而禁止总结时，可以返回合规检索链接，不能借“搜索回答”生成该帖摘要；一个流程实际包含检索、总结或推荐多个用途时，应满足所涉及的全部许可，不能更换功能名称绕过限制。用途对应的具体实现与评估用例须在规格中细化。

**AI-12** 关闭某项用途适用于该账号 / 帖子的后续调用和受影响历史，停止对应上下文构建、索引和缓存使用。普通关键词搜索与社区阅读继续按原可见性运行。重新开启后重新核验内容当前有效性和用途资格，逐步恢复索引，不复活已删除或被其他规则限制的内容。

### 12.4 历史回答撤回与继续对话

**AI-13** 回答须保留足以执行撤权的来源关联，包括直接内容与依赖此前回答引入的来源。原帖删除、失去阅读资格、被拉黑、审核限制或作者撤回有关 AI 用途后，相关原文、摘要、引用和实质依赖它的回答停止展示及继续作为上下文使用。

**AI-14** 有可靠来源追踪时，可重新生成不依赖撤回来源的回答；不能可靠区分受影响部分时，隐藏整条受影响回答并标记不可用。不能只移除来源链接仍保留原回答，也不能让下一轮从隐藏回答“记忆”中重述。未受影响的本人输入与合法回答可保留。

**AI-15** 打开历史、复制、继续提问、重试和来源跳转都执行当前校验；权限变化事件用于及时刷新，但安全不能仅依赖事件成功送达。离线不能展示无法重新核验的受限内容及依赖它的回答。已看过、截图、复制到系统外的回答以及系统无法控制的第三方副本无法保证收回。

### 12.5 会话管理、额度与恢复

**AI-16** 支持新建、查看历史、打开旧会话、自动简短标题、修改标题、删除会话、停止生成、复制合法回答、失败重试及基本反馈。历史与标题仅本人可访问；删除立即从 UI 和正常检索移除，物理清理见第 16 节。会话标题也不能保留已失权内容的敏感摘要。

**AI-17** 保存请求状态并区分提交中、检索中、生成中、已完成、已停止、失败和结果待确认。超时 / 断网保留输入和已合法保存历史，不把半截回答标成完成；重试沿用可追踪请求关联，避免重复气泡、重复额度和重复计费账目。服务商是否已收费无法确定时记录并对账，不直接判为免费失败。

**AI-18** 封闭内测免费使用 AI；已确认默认每用户每日最多 20 次成功完成请求，最大输入 8,000 Token（含检索上下文）、最大输出 2,000 Token。每日额度按后台可配置时区重置；额度、Token 上限、模型参数及合理范围内的授权用户组 / 不同 AI 功能限制统一配置。明确失败且未成功完成的请求不重复扣额度；结果不确定记录状态并对账，服务商实际成本独立记录，停止生成可能已发生的成本不能抹除。默认额度已获产品确认，实际模型兼容与费用仍须验证。

**AI-19** 支持单用户请求 / 成本保护、单次预算、全局每日预算、预算告警和高成本调用保护，由获授权管理员通过统一配置中心管理。并发请求不能突破额度或多次扣同一成功请求。用户额度耗尽、模型限流或全局预算保护时明确说明限制及可知恢复时间，保留输入；全局保护可以暂停新 AI 请求，不能跳过授权或转给未经批准的服务商；可展示普通授权搜索作为恢复入口。具体成本金额仍未给定。

**AI-20** AI 故障不阻断普通社区浏览、发布、互动和私信。后台通过统一配置中心管理已批准服务商 / 模型 / 推理区域 / 保留和日志策略、MCP 工具启停、超时、重试及成本参数，提供错误、延迟、Token 和实际 / 待对账成本统计；工具配置不能扩大只读能力或用户资格。原始对话访问需另行授权与审计，不因 AI 运维角色默认开放。

## 13. 分享网页、搜索引擎与外部副本

## 14. 治理、处罚、申诉与后台

来源：S03、S04、S05、S07、S08、S14、S21。

### 14.1 内容审核与举报

**GOV-01** 基础发布检查与发布后巡检结合。通过必要检查的正常内容可发布；待进一步确认的进入待审核或限制展示。作者可查看、编辑、撤回 / 删除待审核内容及允许公开的处理说明。待审核内容不进公共信息流、搜索、热门、推荐或普通 AI。

**GOV-02** 举报帖子、评论、账号、私信；保存举报对象、理由、必要证据与提交结果。状态至少有待处理、审核中、已处理、不予处理；用户能查看允许披露的进度和反馈，不暴露举报人身份、其他人的证据或内部敏感处理信息。

**GOV-03** 举报多不等于违规。审核员基于证据可提醒、限制传播、删除内容、限制账号功能或封禁，并记录原因、操作人、时间、对象、必要依据与结果；涉及高影响自动处罚时可人工复核。紧急先限制传播也须留记录与复核。

**GOV-04** 基础垃圾内容、骚扰、重复违规、异常互动、重复发布与协同刷量防护。可配置限流与风险阈值，但不能跳过授权或用运营伪造计数。举报提交与受理故障分别展示，避免提交失败却显示已受理。

### 14.2 处罚与恢复

| 处罚类型 | 新操作 | 既有合法内容 | 用户与治理入口 |
|---|---|---|---|
| 功能限制 | 仅停止决定中列明的功能 | 原则继续展示；独立内容处置仍生效 | 显示原因、受限功能、开始 / 结束时间和申诉 |
| 临时封禁 | 指定期间禁止发布和互动 | 原则可以合法阅读，但从推荐 / 热门暂移除 | 受限入口可读处罚、期限与申诉状态 |
| 永久封禁 | 禁止发布和互动 | 从正常信息流 / 搜索 / 推荐移除；主页 / 直接链接为适当占位 | 保留必要处罚说明、申诉及独立证据授权 |

**GOV-05** 账号处罚、单条内容处置和用户主动删除分别记录；一次账号处罚不能证明所有帖子违规，也不自动永久删除所有文件。到期或撤销只恢复该处罚实际影响、尚有效的状态，再检查当前权限、拉黑、原帖、审核和媒体依赖。

**GOV-06** 不恢复用户主动删除内容、已过期请求或主动取消的关注，不自动解除拉黑；申诉恢复不是全部关系回滚。记录恢复决定和执行结果，有失败重试，避免显示账号已恢复而对应资源错误暴露或长期被错误隐藏。

**GOV-07** 受影响用户可提交理由与必要材料并查看申诉状态。不同于原处置人的有权人员最终复核，原处置人可补充说明但不能独自决定。没有第二名合格复核者时进入待复核，不以自审代替；审核人只访问该案所需证据。

### 14.3 后台角色与操作范围

| 角色 | 可执行范围 | 不因角色自动获得的权限 |
|---|---|---|
| 超级管理员 | 管理管理员、授权与撤销、邀请资格、全局安全和系统配置；首版负责开发者邀请、插件版本审核通过、敏感权限与生产发布确认，自用可兼任且分别留档；高风险操作再次验证 | 无理由浏览所有私信、草稿、AI 对话或跳过证据授权；插件角色兼任不豁免独立申诉复核 |
| 内容审核员 | 处理举报、帖子 / 评论 / 投票 / 媒体审核、违规记录、授权范围内的警告和封禁、必要历史版本 | 数据库凭据、全局安全配置、无关私人会话 |
| 社区运营员 | 话题、公告、置顶 / 精选 / 推荐位及汇总运营指标 | 私信、私人草稿、完整 AI 对话及默认处罚权 |
| AI 运维员 | 经授权的服务商 / 模型 / MCP 配置，调用故障、延迟、Token 与成本 | 默认内容处置权、完整私人输入输出、其他用户资源 |
| 审计只读员 | 已授权审计记录和系统事件 | 修改、删除、处罚和任意用户正文 |

**ADM-01** 后台包括运营总览、用户搜索与管理、封禁 / 解封、帖子 / 评论 / 投票管理、媒体管理、举报 / 审核 / 申诉队列、话题 / 公告 / 推荐位、违规记录、角色权限、审计与系统配置。对应真实数据，不以 Kiranism 示例页面当交付。首版还交付插件管理、扩展页面、发布 / 日志 / 恢复与开发者支持，见第 24 节；自用及受邀审核接入，首版由超级管理员按 PLG-01 负责审核 / 敏感权限 / 生产启用确认，权限限于适用环境与插件且受核心角色约束。

**ADM-02** 权限按角色、具体操作及资源分别授予，后端每次验证；能打开页面不等于能执行页面上的全部操作。未经授权导出、敏感数据读取或配置变更必须拒绝；没有确认的业务导出场景不默认开放全库导出。

**ADM-03** 管理员手机号 OTP + 额外 MFA，优先评估 TOTP；只有 OTP 不能执行后台高权限操作。封禁、敏感查看、导出、角色 / 密钥配置、插件敏感权限 / 生产确认及主动永久清理等高风险操作按风险再次验证并填写原因。权限撤销、过期和退出后的后续敏感操作拒绝，不仅前端关闭按钮。

**ADM-04** 首位超级管理员由部署负责人在受保护一次性初始化中建立，完成后关闭入口；后续由有权人员邀请 / 创建并授权。普通注册不能成为管理员。账号权限与 MFA 的服务端强制程度由方案验证。

**ADM-05** MFA 丢失不只靠短信恢复全权限；依靠可信部署 / 服务端访问、归属核验、一次性恢复凭据和审计。多人时优先另一超级管理员复核；仅一人时采用受控紧急恢复，不公开可滥用的接口。恢复后撤销旧会话 / 凭据并通知。

**ADM-06** 敏感操作和必要敏感读取写服务端审计：操作人、时间、对象、动作、理由、结果及可追踪请求关联。日志访问受控，避免记录凭据、完整对话和不必要个人内容；普通修改接口不能任意篡改审计。

**ADM-07** 管理员原则上不任意阅读私信。只有具体举报或必要安全事件，按授权访问相关最小证据并审计；运营、AI 运维与审计角色不能借统计或日志越权读取。证据、业务原文和物理保留独立授权。

插件开发者、包维护者和发布管理者不因插件业务页面取得任何上述角色的默认私有数据权限；后台插槽、权限审核、版本发布与恢复能力见 EXT-02、PLG-01–06 和 UPD-01–05。

## 15. 媒体、缓存、离线与撤权

来源：S06、S07、S08、S23。

### 15.1 访问分级

| 等级 | 范围与策略 | 撤权与验证 |
|---|---|---|
| 普通公开帖子附件 | 同样优先私有 Storage Bucket；系统可控的新访问检查当前内容有效性和授权 | 删除 / 收紧后，失权者的后续新访问立即拒绝；旧地址和缓存命中也须满足，不能默认永久 URL |
| 普通关注者可见媒体 | 私有 Bucket；新访问检查当前身份、资源与依赖，签名和缓存方案由技术核验 | 撤权后新访问立即拒绝；暂定短签名 60 秒不是可接受残余窗口，不能单靠到期实现撤权 |
| 仅自己可见、私信附件、私人草稿、举报证据及需严格撤权内容 | 受保护接口逐请求检查当前身份、资源与依赖，不共享缓存，不用可长期复用签名 | 后续新读取立即按当前资格拒绝；不能只依赖 JWT / 签名过期 / 客户端清理 |

**MEDIA-01** 媒体、缩略图、GIF、视频分片、预览与下载均继承所属内容及关联依赖授权。外部对象地址不应成为绕过 Supabase RLS 的入口；高权限凭据只在可信服务端受控使用，不进入客户端包。

**MEDIA-02** 签名有效期、CDN 缓存 TTL、应用缓存与会话令牌是不同控制；Auth 密钥轮换不能当即时撤销文件签名保证。所有媒体在系统可控的后续新访问上执行当前资格，撤权即拒绝，不能等待签名或缓存过期。验证旧链接、缓存命中、重连、离线、多端、账号退出 / 注销、权限收紧、被拉黑和关系变化后的实际表现；测量发现的撤权后继续访问属于须修正的缺陷，不能因小于暂定签名时长而接受。

**MEDIA-03** 离线不展示无法重新确认权限的他人受限帖子、媒体及依赖回答，曾经有权不授予永久离线授权。本人的未发布本地草稿按草稿规则保留；退出时清理应用管理的受限缓存、URL 与会话关联，不把草稿恢复与失权内容访问混为一谈。

**MEDIA-04** 永久删除同步清理实际对象、关联记录、派生文件、索引和应用管理缓存；单用户撤权不删除其他合法用户需要的共同对象。删除恢复期和具体证据保留不维持普通业务可读。已下载、截图或外部另存无法可靠收回，须与系统可控撤权明确区分。

### 15.2 发布校验与播放

**MEDIA-05** 服务端校验文件类型、真实格式、大小、时长、归属和必要审核；UI 选择通过不是服务端认可。未知 / 不支持格式、安全检查失败、超限和处理超时保留草稿并给具体恢复方式。首版复杂视频转码不擅自扩大，但必须满足已批准格式的播放；格式清单和兼容方案由技术核验。

**MEDIA-06** 视频默认仅 Wi-Fi 静音自动播放、蜂窝点击；提供始终、仅 Wi-Fi、从不自动播放及关闭预加载设置。GIF 在可视区可播放，尊重减少动态效果及省流量；离开可视区暂停或合理降耗，用户可主动开启视频声音。

## 16. 数据保留、删除与恢复机制

来源：S05、S07、S08、S13、S14、S21。下表时间已于 S14 作为**默认保留策略**确认，须纳入后台分类配置并验证实际清理能力；备份 90 天仍是待验证的轮转目标。即时业务隐藏和撤权不能等保留期满才执行，调整期限不能撤销已生效的访问收回；S21 的卸载保留不覆盖既有期限或删除义务。

| 数据分类 | 立即业务效果 | 已确认默认保留 / 清理策略 |
|---|---|---|
| 注销账号资料 / 认证关联 | 禁止登录，停止关联内容正常展示、移除个人索引 / 关系 | 主数据 30 天内删除或不可逆匿名化 |
| 注销作者帖子 / 评论 / 媒体 | 不再正常可读；只保留不泄露身份 / 原文的必要结构占位 | 30 天内删除 / 匿名化，独立有依据证据除外 |
| 注销用户备份 | 不允许经恢复重现已生效删除数据 | 目标 90 天内轮转清除；恢复必须重新应用删除记录 |
| 已送达接收者的私信 | 发送方注销后显示已注销，无身份链接；本人删除单条立即隐藏并撤销消息 / 附件正常访问，对方合法访问独立保留 | 默认最后会话活动后 24 个月进入过期清理流程；一方删除不直接物理删除共享数据，在另一方仍有权时保留必要数据，待双方均不再需要、保留期限届满或其他适用条件满足后清理 |
| 用户主动删除帖子 / 评论 | 正常内容及附件访问停止；可撤销 / 最近删除管理 | 10 秒撤销、30 天恢复期；到期永久清理，不提前毁掉唯一恢复副本 |
| 主动删除 AI 会话 | UI、检索和上下文立即移除 | 30 天内清理会话、可重建索引及缓存 |
| 未主动删除 AI 会话 | 本人可读，来源仍按当前权限校验 | 连续 12 个月无活动进入过期清理流程，提前说明实际策略 |
| AI 调用元数据日志 | 只记录模型、时间、耗时、Token、费用、错误与必要请求关联 | 30 天，不默认完整提示词 / 回答 |
| 必要受控 AI 原始调试输入输出 | 明确启用、敏感字段限制、独立访问审计 | 最长 7 天 |
| 举报证据 | 仅具体案件授权使用，不进普通业务 / AI / 搜索 | 结案后 180 天，有理由 / 授权才可延期 |
| 管理员审计 | 限制访问，避免不必要原文 | 1 年 |
| OTP / 认证安全日志 | 最小反滥用记录，不记录可使用验证码或秘密 | 30 天 |

**DATA-01** 业务数据库、Storage、派生媒体、AI 会话、全文 / 向量索引、缓存、日志与备份分别有清理责任和可查状态。各类默认保留时间、触发条件、过期与例外策略由后台独立配置，日志与证据分别配置清理、访问和延期规则。删除 / 匿名化失败可追踪重试，不能只从 UI 消失就声称数据全部删除；调整配置不能让已经删除的内容自动公开或恢复已撤销访问。

**DATA-02** 依法或为有效争议确需保留的最小证据独立授权、明确理由 / 期限 / 责任人，不以审计为由无限保留所有个人信息。确需延长日志或证据保留须有明确理由、授权与审计；原始 AI 输入输出不默认长期记录，访问受控且避免不必要个人信息。异常延期、恢复与清理形成审计；普通日志配置不能关闭必要安全审计或绕过适用的数据保护要求，保留副本不能重新接回普通业务输出。

**DATA-03** 同一资源兼具恢复目的、案件证据或多个会话参与者的合法保留需求时，按各自授权分别管理。私信单条删除立即撤销本人的消息 / 附件正常访问；另一方仍有权访问时继续保留必要共享数据，不因一方操作直接物理删除。待双方均不再需要、保留期限届满或其他适用条件满足后清理，独立证据按 DATA-02 管理；保留记录、会话重现及备份恢复不能恢复已撤销的本人访问。

**DATA-04** 备份恢复后，先重放删除 / 撤权 / 处罚及有效隐私设置，再开放业务读取；验证备份不会复活注销账号、被删内容或已撤回 AI 来源。RPO / RTO、备份周期和可行轮转期限由部署方案提出，产品确认后验收。

新增插件同样登记业务数据、Storage、索引、缓存、日志及备份的生命周期和责任。停用 / 卸载 / 升级分别处理代码、配置、数据库结构和业务数据，共享内容、恢复副本与证据不能因卸载被直接误删；所涉授权继续按本节和 PLG-03–05 执行。S21 确认卸载默认保留业务数据并继续已批准的分类期限与清理义务，卸载 / 再安装不重新起算保留期；插件缺席时核心仍维持必要删除、撤权、治理证据和到期清理。卸载时额外主动永久清理须单独授权确认，原有已批准到期清理继续执行；兼容重装只恢复仍有效且有权的数据，不复活已删、已清理或已撤销访问的记录。

### 19.2 统一运行时配置中心

来源：S14–S18。统一配置是首版核心交付，覆盖 Expo UI 移动端、Supabase 服务端、Kiranism 管理后台及 AI/MCP 的业务模块；官方及受邀插件同样必须接入。可调整业务规则、限制和运营阈值集中管理，不在组件、API、数据库函数、Edge Functions、定时任务、AI 工具或后台页面分别维护不一致的常量。已确认业务规则与默认值作为初始配置；可配置不表示未实现代码已可用，也不替代插件审核或生产启用确认。

**CFG-01** 服务端是业务配置的权威来源；App、后台和 AI/MCP 从同一受控配置能力取得适合当前环境、用户和模块的有效规则。前端只获得需要展示和交互校验的非敏感配置，不读取服务商秘密、其他用户配置或后台专用安全策略；凭据仍按秘密管理处理。

**CFG-02** 每项参数登记名称、唯一标识、业务说明、所属模块、当前值、默认值、数据类型、有效范围、环境、作用范围、依赖与冲突、修改权限、生效方式及必要重载条件。新增任何可调整业务参数同时明确配置入口、默认值、校验范围、生效行为和验收标准，不只加一个孤立字段。

**CFG-03** 至少覆盖下表的全部已确认模块，不以只配置帖子长度或 AI 额度代替统一能力。数量、时长、频率、开关和已实现的策略均有管理入口；未经确认的新业务能力不能因出现配置字段而进入首版。

**CFG-04** 支持全局默认、适用环境、模块 / 插件及经授权用户组的作用范围；规定明确、可查的优先级、覆盖与冲突处理，输出唯一有效配置。插件参数、菜单、主题及已实现业务规则在授权范围内调整，不引入社区级或租户级运营配置。合并机制由正式方案记录；用户授权、数据隔离和作者设置不能被配置覆盖放宽，个人接收、回执等偏好仍按原流程管理。

**CFG-05** 配置具备版本、有效范围、生效时间和状态；后台明确哪些变更立即生效、定时生效或需要重载。关联参数按兼容的完整版本生效，避免同一操作读取互相矛盾的限制、权限或期限；客户端与服务端能够识别版本，方案明确更新传播、兼容与失败处理。

**CFG-06** 客户端可缓存非敏感配置并及时刷新；其显示与交互校验使用当前适用配置。客户端与服务端规则不一致时以服务端为最终依据，提示限制变化并刷新，保留用户输入及可恢复提交状态。可见性、资源权限、账号状态及敏感操作每次在服务端重新检查，缓存不成为授权凭证。

**CFG-07** 普通运营人员只修改获授权参数；敏感配置、权限策略、服务商凭据和系统安全配置由更高权限管理，高风险操作遵循 ADM-03。变更记录操作人、前后值、时间、原因、配置版本及结果；可能造成全站故障或数据风险的变更提供确认提示、变更预览和必要恢复机制，不因能打开配置页面而获得修改所有字段的资格。

**CFG-08** 发布前校验类型、范围、依赖、冲突和作用范围，拒绝非法值与不兼容组合；失败不能留下部分生效的关联配置。支持必要回滚和可查恢复结果，回滚前仍验证权限、兼容与当前状态。缺失、故障或不兼容配置不能退回无限额度、强行启用功能或跳过安全检查；最后合法配置与明确失败策略由方案落实。

**CFG-09** 真实业务校验统一在服务端执行，API、数据库函数、Edge Functions、作业及 AI/MCP 使用同一有效配置；前端及时提示超限但后端仍校验。前后端与后台不能各自写死一份阈值，也不能因提高参数或关闭前端提示就取消服务端验证。调整所影响模块的消费路径、并发和配置更新竞争纳入验收。

**CFG-10** 身份认证、服务端授权、RLS、敏感数据隔离、密钥保护和必要审计持续执行。策略可以提供经过授权的配置能力，普通业务参数不能关闭核心检查或授予未授权资源访问；AI 工具 / 模型配置不扩大只读边界、作者许可或已批准的数据处理地域。已实现业务策略的调整须通过权限与依赖校验，不能把安全保护当任意开关。

**CFG-11** 每项涉及期限、状态或资格的配置明确生效对象、时间及现有资源的处理规则，变更预览说明影响。调整或回滚不能恢复已生效的数据撤权、自动重新公开已删内容、复活结束请求、破坏既有投票与锁定状态，或绕过独立处罚和证据授权；恢复、申诉、重新申请等仍走各自合法业务流程。

**CFG-12** 调整已实现的运行时参数尽可能无需重新构建 App 或部署服务；帖子长度、投票时长、AI 额度、媒体大小、证据期限与推荐权重按规定生效。新增代码、原生能力、数据库结构、不兼容接口或底层安全架构仍可能需要构建、部署或迁移，不承诺参数能凭空实现新功能。

**CFG-13** 主题、颜色、菜单、导航、页面模块显示、默认排序和语言选择只配置已实现且当前支持的界面能力；保持中文默认、无障碍、读屏名称与有效功能反馈。显示 / 隐藏入口不替代服务端授权，也不能虚构可用 AI 能力、认证或尚未支持的语言；后台展示当前作用范围、生效方式及结果。

### 20.5 GitHub Actions 云端编译、测试与实际验收

来源：S19及ED-22。以下完整覆盖用于产品正式验收；日常开发按CI-01执行当前目标和直接受影响回归。以下为已确认的全项目交付要求，适用于全部原有和新增功能，包括 AC-01–54、性能 / 容量 / AI 评估及插件开发样例。当前 PRD 修订不表示自动化工作流已经实现或云端验收已经执行。

**CI-01** 按实际变更与风险执行真实测试和必要回归；日常目标用例＋直接受影响回归，Actions按可用业务切片批量、按需独立复验。关键权限、安全、数据完整性和缺陷修复必须有效测试；保留真实结果及必要日志，不伪造通过。（ED-22）

**CI-02** 流程覆盖全部移动端 iOS / Android、Supabase 服务、Kiranism 后台、分享网页、AI/MCP、前后端集成、官方业务模块和受邀插件。纳入功能编译、功能测试、接口测试、权限与安全测试、回归、端到端、布局 / 样式、交互和视觉验收；包括插件安装 / 启停 / 升卸、依赖兼容、迁移 / 恢复、隔离及配置变化。建立需求 / 验收与检查项对应关系，不能只测试改动页面或用单端通过代表整体通过。

**CI-03** 前端、后端与后台须在 Actions 云端驱动的真实可执行环境中实际启动并完成验收：移动端安装 / 运行对应原生产物，浏览器实际打开运行中的页面，后端运行隔离的 Supabase 服务、数据库、认证、Storage / Realtime 及适用函数，与前端和后台联通验证。单元测试和模拟依赖可辅助定位，但不能替代真实接口、授权、数据库逻辑及跨端业务流程；仅代码检查、编译成功或工作流文件存在不能判为通过。

**CI-04** 视觉验收针对实际页面的布局、样式和交互表现自动检查，覆盖移动 App、管理后台、分享网页和插件扩展页面 / 插槽。按已确定设计和适用设备、视口、主题、字号、键盘及加载 / 空 / 错误 / 权限 / 内容状态验证排版、颜色、尺寸、遮挡、溢出和可操作性；记录实际渲染截图、差异与交互执行结果。概念 HTML、静态图片、源码样式或只有截图而未执行交互不算完整验收；移动原生 UI 不由 Web 页面代替。

**CI-05** 正式验证结果由Actions自动记录；本地开发结果记录真实local来源、必要命令／结果与失败日志，不伪填run。正式结果关联提交SHA、构建产物及 App / 后端 / 后台 / 插件版本、工作流 run、环境 / 配置、用例范围、通过 / 失败 / 跳过、耗时和错误。保存适用的日志、测试报告、截图 / 视觉差异、交互轨迹或录像与构建产物，失败也保留证据；具体格式、保存期限和访问权限留方案确定。记录不得泄露凭据、真实私信、私人草稿或无关个人信息，不把验收证据变成数据授权旁路。

**CI-06** 缺失、取消、超时、基础设施不可用、未执行 / 被跳过的必需检查或缺少实际运行证据均不得标为通过。提交、插件 / 配置变更及待发布版本执行相应验证与回归；正式交付版本须完成全部必需验收，修复后复测相关流程及必要回归，正式验收时由Actions独立复验。结果与当前版本不符时重新验证；不能由 AI 手改结果、只重跑编译或沿用另一版本报告消除失败。

**PLT-03** 核心平台、内置官方模块 / 插件、第三方插件分别标明来源、维护者、版本、权限、依赖与审核记录。官方业务持续完成原有帖子 / 评论 / 串、关系、互动 / 投票、发现、私信、AI、分享、治理等首版规则，身份安全核心承担相应账号要求。首版允许项目自身及受邀开发者提交，经兼容、安全和权限审核后才能安装到测试或生产；不向所有开发者开放不受限制提交安装。来源不自动赋予高权限，每个更新版本按审核与增量权限规则处理。

**EXT-02** Kiranism 提供管理菜单、独立业务页、仪表盘组件、运营工具、系统配置、AI/MCP 管理和插件管理扩展位置。插件页面使用平台后台认证和角色授权，前端与服务端同时执行逐操作权限；插件作者不能通过新增菜单取得管理员资格。平台管理员可查看入口所属插件、当前状态及失败原因。

**EXT-03** Supabase 服务端提供受控业务 API、Edge Functions、数据库扩展 / 迁移、RLS 策略、事件处理、异步任务、通知和批准的 AI/MCP 工具扩展能力。明确插件能声明和申请的能力、依赖和数据范围，安装时校验，运行时继续授权；迁移、RLS 和服务端代码不得默认拥有无限数据库权力或跨模块资源读取资格。

**EXT-04** 同一扩展的前端、后台和后端声明可关联检查，提供接口 / 事件 / 公共类型与兼容说明。重复入口、命名冲突、缺失依赖或前后版本不匹配须有可查结果，不静默覆盖另一插件功能。事件与任务按插件、环境和请求关联记录状态，重复 / 重试继续符合原业务幂等、通知去重和权限要求；资源限制与具体容错机制留给设计。

### 24.3 发现、安装、权限及生命周期

**PLG-01** 插件具备可读版本化清单，声明身份、来源 / 维护者、包与版本、平台 / SDK / 各端兼容、依赖冲突、权限、配置、插槽、代码 / 原生变化、迁移及数据生命周期。管理端发现 / 导入自用或受邀来源的审核包，展示与具体版本绑定的兼容、安全、权限审核记录；未审或包与审核版本不符不能安装。S21 确认首版由超级管理员负责开发者邀请、认可具体版本审核通过、批准敏感权限及生产发布确认；允许项目自用时同一人兼任开发 / 审核 / 发布，各步骤仍分别操作和留档，不跳过 Actions 验证、MFA、逐操作授权或审计。受邀开发者默认只能提交包，未经另行授权不具有审核、敏感权限批准、安装或发布权；任何另行授权仍不能越过核心角色边界。首版不开放不受限制的公共市场，包来源 / 分发 / 校验机制由方案明确；隔离云端开发调试不等同测试 / 生产安装授权，调试与验证按CI-01–08及ED-22执行本地反馈和按需Actions复验。

**PLG-02** 管理员在指定环境发起安装，系统识别包内容，检查来源、清单、版本、依赖、权限、迁移和目标客户端兼容；仅在授权及所需验证满足后安装 / 注册。发现、获取包、检查、安装、待测试 / 构建、待发布、已启用和失败等结果分别显示，不能将上传成功等同于全部端已上线。具体状态命名与实现留给规格。

**PLG-03** 启用前校验授权、依赖、环境与已发布版本；停用后停止相应新业务入口、写入、调用、作业、事件、通知与 AI 工具，按受控排空规则收束在途操作，不能只从菜单隐藏。S21 确认历史数据尽可能通过声明的受控路径按当前资格只读，无法安全展示时提供不泄露正文的不可用占位；历史读取不授予新业务写入资格，核心必要删除 / 撤权 / 治理 / 清理义务持续执行。有效依赖默认阻止操作，管理员明确选定联动停用后才按预览范围执行，不自动扩散。依赖模块、在途任务、历史展示及核心功能影响在操作预览中说明，具体实现由方案验证。

**PLG-04** 升级检查权限增量、兼容 / 依赖和迁移影响，测试及发布状态可查；新增敏感权限不能随自动升级静默获得。失败尽可能保持最后可用版本，提供可控重试或恢复。代码 / 配置回滚、数据库迁移与业务数据恢复分别说明限制，不能承诺任意结构变化都能一键无损降级；不可恢复风险和必要备份须在执行前明确。

**PLG-05** 卸载分别处置代码、配置、数据库结构和业务数据，不等同直接删库或删除全部业务记录。有效依赖默认阻止卸载并显示清单；管理员明确选择联动停用不等于自动卸载或清理依赖模块。S21 确认卸载默认保留业务数据，继续原已批准分类期限及清理条件，不因卸载 / 重装重置时间或无限延长保留；新插件声明数据分类 / 期限并经审核。卸载时主动永久清理由有权人员另行确认，仍遵守共享数据、恢复副本、证据和删除义务；原已批准的到期清理作业继续执行。兼容再安装可恢复仍有效且当前有权的数据与必要关联，不能复活已删 / 已清理 / 已撤权记录或默认为新版本授予旧敏感权限。卸载预览分别说明代码 / 配置 / 结构 / 数据、必要迁移、历史只读或占位、权限撤销与结果，不能破坏核心或其他模块数据；恢复条件与迁移限制由方案验证。

**PLG-06** 插件管理显示当前 / 目标版本、安装 / 启用环境、权限、依赖、兼容、发布状态、运行健康、请求 / 运行日志和失败恢复入口。日志与治理访问仍需授权，不暴露凭据或无关私人正文。插件自身异常应可定位并按权限停用 / 隔离，核心安全与其他用户 / 插件不因该插件越权或无界资源使用受到影响；共享基础设施故障继续按第 17 节说明真实影响，隔离与资源策略须后续验证。

### 24.4 自动测试、构建、发布与客户端更新

**UPD-01** 安装 / 升级后自动检测变更，通过 GitHub Actions 云端串联兼容检查、全部适用测试、回归、构建、实际运行 / 视觉验收和预发布验证，记录对象、版本、环境与插件、权限、阶段、失败及恢复。**首版正式对生产用户启用前，须超级管理员确认具体版本及作用范围（S21）**；任何实际影响生产用户的部署、迁移、权限生效或版本替换也须经过该确认，不能提前执行后仅批准菜单。获确认后可自动执行适用发布和更新提示；灰度先向管理员明确指定名单开放，扩大范围前再次确认目标范围。后续可支持预授权低风险更新，但不作为首版默认能力。

**UPD-02** 至少区分下表四类更新，不把安装动作等同于任意端立即可用。检测依赖和混合变更后按最严格实际要求形成交付顺序，不能只更新页面却使服务器契约、权限或数据结构不兼容。

| 变更类别 | 产品要求 | 需后续核验的条件 |
|---|---|---|
| 已实现运行时配置 | 按第 19 节版本 / 生效规则更新，尽可能免构建部署 | 配置消费者、缓存与兼容性，不能凭配置产生新代码 |
| 后端 / 后台插件代码与结构 | 执行测试、依赖 / 权限 / 迁移校验及适用部署 | 自部署环境、后台发布、迁移 / 恢复及前端契约 |
| 兼容的移动前端更新 | 符合已安装原生运行环境和平台 / 渠道条件时，通过适用 OTA 流程提供 | Expo UI / Expo 更新机制、运行版本、签名 / 渠道及商店规则，尚未验证具体实现 |
| 新原生能力或不兼容变更 | 触发适用 App 重建和渠道发布 / 更新提示，未兼容用户受控处理 | 原生依赖、构建配置、版本 / 商店审核和安装更新路径 |

**UPD-03** 平台识别客户端版本与原生能力、后端契约及插件兼容条件；不兼容客户端不接收不能运行的扩展代码或可执行入口，给出明确更新 / 暂不可用提示。S21 确认旧版兼容功能继续可用，扩展不兼容时仅停用对应不可运行功能并提示更新，不据此阻断其余安全兼容功能；只有核心无法安全兼容时才强制更新整个 App，并说明原因和有效更新去向。灰度名单不授予不兼容能力或额外数据资格；不能承诺所有插件都免重建 App。具体支持版本、能力识别、必要安全 / 申诉指引与渠道路径由方案落实现有规则。

**UPD-04** 发布支持适用环境与灰度名单、版本状态、健康观察、失败中止与恢复；S21 确认先向管理员指定名单开放，完成相应验证和观察后由超级管理员确认扩大范围，名单外不提前获得新能力。测试不通过、依赖不满足、未经审批权限或不兼容不能被自动步骤跳过。灰度旧 / 新客户端并存时，数据与接口继续授权且兼容，回滚不复活已删除内容、已撤销访问或未授权插件能力；观察窗口、健康阈值和具体机制由正式方案明确并验证。

**UPD-05** 自动流程对失败可重试、恢复和查明最终状态，避免重复安装、迁移、通知或发布；已运行旧版在安全且兼容时继续可用。不能回滚的步骤、部分成功、在途任务及外部渠道待处理状态向管理员明确，恢复策略按代码、配置、结构和数据分别记录；用户不被困在无反馈的半启用状态。

### 24.6 前后端独立调试与服务端隔离

**TST-01** 正式区分云端开发 / 测试和独立服务器生产环境，服务端按真实环境隔离数据库、Storage、账号、凭据、日志及访问；不能只隐藏插件入口充当隔离。提供独立测试数据能力，不默认复制未经处理的生产私信、草稿或用户信息；调试、测试、预览与验证均通过 Actions 云端环境执行，隔离机制、资源供给与费用留方案和 Q-16。

**TST-03** 调试账号 / 令牌与权限限定所属环境和插件范围；测试流程默认不修改生产数据、不发真实私信 / 推送、不影响真实用户。短信、通知、AI 与其他外部副作用按明确测试通道 / 模拟策略管理，仍受费用、数据处理和工具权限约束；必要真实外部集成测试的准入条件待 Q-16，不能由插件自行切换生产凭据。
