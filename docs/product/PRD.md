## 0. 阅读规则与需求效力

本文汇总产品负责人已经给出的需求和后续修正。业务规则以最新明确决策为准；网页概念稿和参考截图用于表达布局，不能新增、删除或覆盖业务要求。

全文使用以下状态，各种状态不能混同：

| 标记 | 含义 | 后续处理 |
|---|---|---|
| 已确认 | 用户已明确要求的功能、约束或规则 | 进入首版规格与验收，除非后续明确变更 |
| 已确认默认值 | 用户已采用的初始数值或策略，须纳入统一配置中心 | 可在授权、有效范围和变更规则内调整；产品确认不等于实际部署 / 清理 / 性能已验证 |
| 暂定 | 用户给出的候选默认值、建议策略或工程基线 | 可用于估算与设计，但须完成对应验证或产品确认；不能写成上线承诺 |
| 待确认 | 尚未作出决定、存在实质歧义或依赖外部核验 | 见第 21 节；不能由视觉演示、供应商默认值或开发者猜测替代 |
| 编制建议 | 本次为补齐交付结构或协调规则提出的建议 | 单独列于第 22 节，尚未获得用户确认 |
| 后续 / 首版不做 | 明确延期或排除的能力 | 只保留扩展边界，不计入首版开发范围 |

除明确标注的暂定、待确认和编制建议外，功能规则来自已确认的用户要求。标为首版的功能必须具备持久化、服务端授权、正常与异常流程及跨入口一致性；不能以“有一个入口”代替业务完成。

S16 已明确插件化平台及开发者能力的产品目标。该目标与安全边界属于已确认要求，但各能力的**首版交付层级仍待确认**，按第 1.6、21 与 24 节办理；不能由“已确认平台目标”推导所有插件能力都必须首版完成，也不能将待确认层级当成已决定延期。第 4–18 节既有首版社交功能继续完整有效，不因封装为模块或插件而删减。

阅读顺序：产品范围与排除项见第 1 节；业务规则见第 4–18 节；候选数值、验收、未决项和编制建议分别见第 19–22 节；来源与交付状态见第 23 节。工程安全细化用于落实既定只读、隔离、幂等和最小权限要求，不表示用户逐字指定了某种实现。

## 1. 产品定位、目标与约束

### 1.1 产品定位与场景

面向所有普通用户的综合社交社区。用户在空闲时间浏览自己关心的内容，分享想法、经历、媒体或问题，通过点赞、评论、转发、引用、关注和私信建立联系。AI 是社区核心功能之一，帮助用户查找真实帖子、理解讨论、发现话题和获取有来源的回答。

平台须支持按维护的标准和接口独立扩展前端、后端与管理后台，未来可承载校园、兴趣及其他垂直社区，避免每种形态反复修改核心源码或复制整套项目。上述具体垂直产品的业务规则和交付版本尚未确定，不因列为扩展示例而直接纳入首版。

主要场景：

1. 新用户通过邀请与手机号验证加入，完善个人资料，选择兴趣并发现可关注的用户。
2. 用户保存草稿、发布单帖或帖子串，获得互动并能编辑、调整权限、删除或恢复内容。
3. 用户切换推荐、关注和最新信息流，通过搜索、话题和用户主页进入讨论。
4. 用户发起评论或投票、转发或引用内容，并在明确的权限范围内继续交流。
5. 陌生人提出一次私信请求，接收者决定是否建立会话；任一方可管理通知、回执、屏蔽和拉黑。
6. 用户向 AI 提问或主动选择一条内容进行分析，通过真实来源核实结论；无结果或服务异常时能够理解原因并恢复。
7. 运营人员处理举报、审核内容、执行授权范围内的处罚和独立申诉复核，查看必要的运营与 AI 服务指标。
8. 插件开发者依据版本化文档和模板创建扩展，在隔离环境独立调试页面、API、数据库与权限，完成打包和完整流程测试，不触达真实用户数据。
9. 平台管理员查看插件来源、兼容、依赖和权限，在指定环境安装 / 启用 / 升级 / 停用 / 卸载；系统识别实际变更类别并执行相应验证、部署与构建，展示失败、发布和恢复状态。

### 1.2 首版目标

首版用户能完成手机号注册登录、资料完善、多类型发布、三类信息流浏览、搜索发现、评论与投票、转发引用、关注审批、一对一私信、AI 社区问答和会话管理。运营人员能通过后台管理用户、内容、媒体、话题、举报、处罚、申诉及 AI 配置。

正确性、权限和隐私是硬性门槛。激活、互动、留存、AI 使用与质量、成本和稳定性先建立真实基线，不虚构增长或预先承诺未确认的经营指标。

插件化是新增的平台目标。其首版范围需明确后与上列完整社交交付一并验收，不能以开放插件入口替代基础社交功能，也不能先承诺未确认的第三方生态规模。

### 1.4 首版不做与延期

- 不做广告、会员订阅、付费内容、打赏、付费私信、虚拟货币、支付、退款、分账。
- 不做独立复杂 Articles 编辑器、专业富文本排版、文章目录；问答、活动等只保留统一内容模型扩展空间。
- 不做群聊、语音 / 视频通话、直播、语音空间、通讯录导入、X Lists、批量关注等未经确认的截图功能。
- 不做多人共同续写、协作编辑和跨帖子串合并。
- 不做“为所有人撤回私信”、公开在线状态、最后活跃时间和具体投票者名单。
- 不做 AI 自动发帖、评论、点赞、关注、私信、修改账号或后台写操作。
- AI 实时外部搜索、图片 / 文件解析、语音、图片生成等真实能力不属于已确认首版交付；仅展示待确认入口。
- 官方认证申请、核验、授予、撤销和认证筛选完整流程后续再做；不提供付费认证。
- 第三方登录、高级 / 地点搜索、指定社区 / 群组可见和复杂机器学习推荐后续评估。

## 2. 技术与复用边界

## 5. 主页、关系、屏蔽与拉黑

### 5.1 个人资料与用户名

**PRF-01** 主页包含头像、昵称、唯一用户名、简介、可选背景图、注册时间和关注 / 粉丝数，支持编辑；内容分类包含帖子、回复、媒体，保留草图中的转发分类。所在地为视觉稿中的可选示例字段，尚未作为必须填写项确认。

**PRF-03** 唯一用户名与显示名称分开，修改须检查格式、唯一性和保留词。已确认默认每 30 天最多修改一次，旧名保留 30 天冷却期、期间其他用户不能注册；频率、格式及旧名保留均统一配置。链接资源和历史提及绑定稳定账号 ID；改名不造成链接指向后来抢注旧名的用户，历史提及显示当前名称。

### 5.2 关注与审批

| ID | 规则 |
|---|---|
| SOC-01 | 默认立即关注；开启“需要批准关注请求”后，仅批准的新请求成为有效关注；关注与粉丝数按有效关系计算，不含待处理请求。 |
| SOC-02 | 开启审批保留已有粉丝；关闭审批只改变后续新增关注，原待处理请求由用户自行处理，不批量自动批准。 |
| SOC-03 | 接收者在独立关注请求列表批准、拒绝或删除；发送者可取消请求；同一账号对同一接收者最多一个待处理请求。反复 / 批量或疑似骚扰额外限流，严重或重复滥用可暂定延长冷却至 30 天或执行账号处罚；服务端限流及冷却不可由重复点击 / 多端绕过。 |
| SOC-04 | 关注请求创建后 30 天过期；对发送者统一展示请求结束，不区分接收者拒绝或删除。接收者拒绝 / 删除后冷却 30 天，发送者主动取消或请求自然过期后冷却 7 天。关注请求与私信请求分别管理状态、有效期与冷却，不互相套用；拉黑持续阻止，不能通过重新申请绕过。 |
| SOC-05 | 取消关注或移除粉丝后，立即失去由该关系授予的受限内容资格；公开内容仍公开。移除粉丝无需先拉黑，不自动解除其他合法权限。 |
| SOC-06 | 无审批时，被移除用户可能重新关注；启用审批则重新申请；要阻止再次关注或互动须拉黑。拉黑后请求持续受阻，解除后仍需满足当前规则和有效冷却。 |
| SOC-07 | 游客只能看公开主页的关系数量，不能开具体名单。登录者可看有权访问的公开账号名单；审批账号名单限本人及获准的关注者。名单 API 同步执行权限、账号状态、拉黑校验。 |
| SOC-08 | 关注审批不自动把公开帖子改成受限，也不自动批准私信请求；接受私信请求不能自动授予关注或私有内容权限。 |

### 5.3 屏蔽与拉黑

| 场景 | 内容屏蔽（Mute） | 账号拉黑（Block） |
|---|---|---|
| 关注关系 | 保留 | 双方有效关注解除；解除拉黑不自动恢复 |
| 默认信息流 / 推荐 | 账号屏蔽完全过滤本人默认内容；关键词 / 话题过滤匹配内容 | 双方内容互相隐藏，不因排序变化重新出现 |
| 搜索 | 默认隐藏；主动选择显示屏蔽内容后，可展示仍有权查看的结果 | 双方不能借搜索绕过关系限制 |
| 普通通知 | 过滤被屏蔽账号的普通 / 推荐通知；安全通知不受抑制 | 不再通过通知暴露对方内容或允许新的互动 |
| 发帖 / 评论 / 提及 / 转发 / 引用 | 不直接改变双方写权限 | 双方新互动受阻；服务端判断，不只隐藏按钮 |
| 私信 | 会话免打扰独立；账号屏蔽不等于断开会话 | 既有历史只读，不能继续发送 |
| 已有公共互动 | 不自行删除 | 点赞、转发、引用等合法记录不自动删除；双方隐藏具体记录，其他有权者仍可见，聚合计数原则保留 |
| AI | 主动推荐 / 热门 / 总结遵循过滤；明确找已知内容时，仍可经授权查找 | 检索、引用和推荐不能绕过拉黑关系 |

**SOC-09** 拉黑保护系统能识别的账号访问与互动，不承诺公开内容对同一自然人绝对不可见。不用侵入性设备追踪保证退出登录或更换账号后不可阅读公开内容；受限内容始终执行资源授权。

**SOC-10** 屏蔽方不向被屏蔽方发送屏蔽通知。账号屏蔽、关键词 / 话题屏蔽、会话免打扰、拉黑、移除粉丝是独立操作，设置说明须体现效果差异。

## 6. 内容、发布、草稿与帖子串

来源：S02、S03、S05、S06、S07、S08、S13、S14。

### 6.1 类型与组合

| 内容形态 | 首版支持 | 组合与边界 |
|---|---|---|
| 普通文本 | 纯文本、Emoji、标签、提及、普通链接 | 已确认默认最多 2,000 字符；统一配置，不把长帖当成多个自动分割帖子 |
| 简化长帖 | 更长连续正文、分段、折叠与展开全文 | 已确认默认最多 10,000 字符；同一条内容，同样支持互动和授权，无复杂独立文章编辑器 |
| 图片 | 文字 + 单图 / 多图、替代文本 | 默认最多 9 张、每张 ≤10 MB；不在一帖中混合图片与视频 / GIF；数量、大小及组合规则统一配置 |
| 视频 | 文字 + 一个视频，预览 / 播放 | 默认最多 1 个、≤200 MB 且 ≤5 分钟；不与多图混排；允许格式与实际兼容须验证 |
| GIF | 文字 + 动态附件 | 默认最多 1 个、≤15 MB；按动态媒体处理，与图 / 视频不混排 |
| 链接 | 正文多个普通链接、最多 1 个链接预览卡片 | 标题、摘要、缩略图、来源域名；预览失败 / 超时 / 目标不可访问不影响正文链接展示和复制 |
| 投票 | 问题、单选选项、可选说明、截止时间 | 不与图片 / 视频 / GIF 混合；结果和编辑见第 7 节 |
| 转发 | 与原内容稳定关联 | 不复制可永久展示的正文，不能扩大原内容授权 |
| 引用 | 仅附加文字 + 原内容关联预览 | 首版不能额外附加图片、视频或 GIF；原帖被删除 / 不可见时整条引用含附加文字停止展示，只保留不可用占位 |
| 帖子串 | 作者按顺序连续创建 / 续写 | 每条遵循相应类型组合；整串统一权限、批次原子发布 |

**POST-01** 采用统一内容与关联体系，表示作者、类型、正文、附件、标签、提及、原帖引用、串顺序、状态、当前权限、编辑标记和有效互动。具体数据库拆表与评论实现方式由方案设计，不在 PRD 虚构为已完成。

**POST-02** 标签可进入话题检索和讨论；提及绑定账号 ID。每帖最多展示 1 个链接预览卡片，正文可含多个普通链接；预览生成失败、加载超时或目标不可访问不影响正文链接展示和复制。链接抓取必须处理无效、重复、恶意、超时和加载失败；服务端防 SSRF 等不可信输入风险。内部受限帖子的外链 / 引用预览不能公开泄露正文或缩略图。

### 6.2 发布闭环与状态

**POST-03** 用户编辑时保留文本、选定附件和元数据。发布状态明确区分：草稿 → 上传中 → 待提交 → 发布中 → 结果确认 / 成功或失败待重试；内容审核状态独立，提交成功可能进入待审核，而非一定已公开。

**POST-04** 每次逻辑提交使用唯一标识并服务端幂等。响应丢失或超时而结果不确定时，先查询最终结果；不能直接重新创建第二条帖子。重复点击、重连和强制关闭不产生重复帖子、评论、私信或计数。

**POST-05** 上传失败保留成功附件和正文，只重试失败文件；提交失败不清空输入。区分网络、身份 / 权限、文件类型、大小、审核 / 服务端错误；分别提供重试、修改输入、重新登录或保存草稿入口。

**POST-06** 媒体在正式发布与审核许可前仅暂存，不公开未完成内容。失败批次可复用上传结果，孤立暂存对象有清理机制；清理不得删除仍被有效草稿 / 已发布内容使用的对象。

### 6.3 草稿

**DRF-01** 登录用户文字草稿与元数据保存于 Supabase，并同步本人多个设备；编辑中的本地临时保存用于断网恢复。访客草稿仅在当前设备，登录后由本人选择导入，不静默传入账号。

**DRF-02** 多端编辑发生冲突时提示选择 / 恢复，不静默覆盖较新版本。上传状态和可复用附件由方案明确；不承诺不同设备可以访问仅存在本机的未上传文件。

**DRF-03** 草稿仅本人及明确授权的系统流程访问，不进公开搜索、推荐、热门或默认 AI。主动选择本人草稿交给 AI 的边界见第 12 节。注销按数据清理规则处理。

### 6.4 帖子串

**THR-01** 只有原作者续写，其他人用评论、转发与引用参与；保留连续顺序和完整串跳转，每条独立保存编辑与互动记录。

**THR-02** 一次创建 / 续写提交中的各条记录与关系准备完成后统一可见；初始整串原子发布，续写批次不得对外出现只成功了前几条的半成品。上传任一步失败保留草稿，不泄露暂存附件。

**THR-03** 创建与后续整体修改采用统一可见范围；串内不能单独扩大一条的权限。收紧立即阻止新的业务访问，放宽至公开须提醒并确认整串及符合发布规则的附件将开放。外部副本不能可靠收回。

**THR-04** 删除首帖时整串退出公开展示、搜索、推荐与 AI；删除中间帖保留必要的顺序占位，不公开其正文 / 媒体，不删除其他人的合法内容或错误串联后续帖子。整串恢复与依赖规则见第 9、21 节。

## 9. 编辑、可见性、删除与恢复

### 9.1 编辑与版本

**EDIT-01** 正常帖子发布后允许编辑正文、标签和图片替代文本，即使已收到互动；不替换已发布媒体，不改变原引用关系。长帖遵循同一规则，投票语义遵循 POL-02。

**VIS-02** 推荐、普通搜索、AI/MCP、网页、通知、媒体、版本和缓存的输出都不得扩大授权。正文、摘要、缩略图、标签、关联引用者附加文字和结果卡片同样是内容，不可仅保护详情正文。

**DEL-03** 管理员违规删除 / 依法限制不通过普通最近删除恢复，走复核 / 申诉。到期永久清理后不提供普通恢复；法定或争议证据独立授权保留，不能继续被业务检索使用。

**DEL-04** “立即不可访问”与“后台物理清理”分开：恢复期内为恢复目的保留的对象必须受保护，不提前删除需要恢复的唯一副本；到期清理实际对象、引用与索引。严撤权访问 / 普通媒体残余窗口见第 15 节，不能把后台清理未完成当成继续访问理由。

| FEED-02 | 支持分页、下拉刷新，避免重复，切换保留合理浏览位置；删除 / 收紧 / 审核 / 关系变化后不能依赖旧缓存继续展示失效内容。 |
| FEED-03 | 冷启动选择兴趣、主动关注推荐用户；行为不足时用兴趣、近期公开内容、审核合格内容和运营精选，不伪造热度 / 用户量 / 互动。逐步引入真实行为，不要求复杂机器学习系统。 |
| SEARCH-01 | 搜索帖子、用户、话题；提供时间 / 内容类型筛选、关键词联想、搜索历史管理和清除；所有结果含建议 / 摘要 / 数量也遵循权限与内容状态。 |
| SEARCH-02 | 提供热门话题 / 趋势、热门帖子、最新入口与推荐用户。按真实近期互动增长、独立参与用户、时间衰减与反作弊等排序，不能仅累积点赞；数据不足展示近期讨论 / 最新。 |

## 11. 一对一私信与独立请求箱

来源：S03、S05、S06、S08、S13、S14。

### 11.1 接收范围与会话资格

**DM-01** 正常会话支持文本、Emoji、图片、GIF 和链接，包含会话列表、全部 / 未读筛选、查找用户发起私信、消息时间、实时收发、未读同步、免打扰、举报与拉黑。首版不做群聊、语音 / 视频通话和为所有人撤回。

**DM-02** 默认允许有效关注者直接发送私信，陌生人可发送一条私信请求。接收方可关闭陌生人请求、调整接收范围或关闭全部私信，拉黑关系始终优先。本文中的“关注者”指发送者当前关注接收者，不把反向关注或待审批请求视为资格；未开启关注审批时，陌生人成功关注后即取得关注者资格，可依当前接收设置直接发私信。仅已认证用户的接收范围留作后续认证能力，不在首版伪造认证资格。

**DM-03** 已接受的正常会话不因关闭陌生人请求、取消关注或开启关注审批而自动终止；任一方拉黑、关闭全部私信或系统安全限制后停止新消息。每次发送再次检查双方身份、会话状态、接收范围、拉黑与处罚。

**DM-04** 已接受的私信会话不授予关注者可见帖子、名单或其他资源的阅读权限；批准关注也不自动接受一个已有私信请求。查找接收者、发送请求和接受请求分别授权。

### 11.2 陌生人请求状态

| 状态 / 操作 | 接收者体验 | 发送者体验与服务端规则 |
|---|---|---|
| 不满足接收设置或被拉黑 | 不建立请求或会话 | 不允许提交；只提示当前不能联系，不泄露对方具体隐私设置 |
| 初始请求提交 | 独立请求箱中一条待处理消息 | 每对账号最多一条待处理请求；只能一条文本 / Emoji，不允许图片、GIF 或链接 |
| 等待处理 | 可以阅读请求、接受、拒绝、删除、举报或拉黑 | 不能追加消息、重复创建或借修改请求反复提醒 |
| 接受 | 进入正常会话 | 初始请求保留为会话起始消息；后续可按当前资格发送正常媒体 |
| 拒绝 / 删除 | 从待处理列表移除；保留必要举报 / 反骚扰入口 | 统一“请求已结束”，不揭示具体操作；默认结束后 30 天不能重新申请 |
| 自然过期 | 默认创建后 30 天自动退出请求列表 | 同样展示结束，默认过期后再冷却 30 天；过期与冷却是两个期限 |
| 发送者主动取消 | 不再保留待处理请求，已结束不重新激活 | 统一结束状态；默认取消后冷却 7 天，不套用拒绝 / 删除 / 过期的 30 天冷却 |
| 拉黑 | 既有仍有访问资格的正常历史只读，停止联系；受拉黑阻止的旧请求不再激活 | 冷却到期也不能再次请求；解除后新请求重新按当前关系、设置和有效冷却判断，不能重新激活旧请求 |

**DM-05** 以上转换由服务端保证，处理过期、接受与重复请求的并发竞争；过期后不能接受旧请求。请求默认有效期 30 天，拒绝 / 删除 / 自然过期后冷却 30 天，主动取消后冷却 7 天，已于 S14 确认；不同结束原因、单用户请求限制和防骚扰阈值分别统一配置，与关注请求互不影响。发信限流、请求限额、账号风险和关系冷却分别执行，不能通过多端、重装、重复点击或重新申请绕过拉黑。

**DM-06** 接收设置改变时，不将待处理请求自动转为正常会话。关闭全部私信后，已有待处理请求保留至原过期时间，可查看、删除和举报，但不能接受；重新开启后仍有效的请求可正常处理，不重置有效期。已结束、已过期或已被拉黑关系阻止的请求不能重新激活；处理与发送均重新校验当前状态和拉黑关系。

### 11.3 发送结果、未读与删除

**DM-07** 发送状态区分本地待发送、发送中、服务端已保存、接收端已送达、已读、失败和结果待确认。系统推送被接受不代表对方设备已收到，更不代表对方已读。断网保留输入；结果不确定先按提交标识查证，重试不能产生重复消息或未读计数。

**DM-08** 消息、请求与未读状态保存在服务端；实时连接断开后重连同步，不仅依赖瞬时事件或操作系统推送。多端阅读后的未读最终一致，历史分页与实时到达不能重复显示。会话免打扰只影响提醒，不阻止消息存储或同步。

**DM-09** 删除单条私信立即从操作用户会话视图隐藏，并撤销其通过正常应用 / API 访问该消息及附件的权限；另一方已经收到的消息与合法访问不受影响。不能因一方删除而直接物理删除共享记录，清理遵循第 16 节。删除整个会话只移除本人的列表项，对方历史不变；再次收到合法新消息时重新出现，仍有权且未被本人单条删除的原历史可见，不能恢复已撤销的单条消息 / 附件资格。删除会话不解除拉黑、不接受请求、不重开结束状态。

**DM-10** 已读回执默认关闭；只有双方都开启时才互相显示已读，任意一方关闭后双方均不显示回执，本人未读数量和标记不受影响。已读回执和正在输入提示可分别关闭；不展示公开在线状态或最后活跃时间。输入信号短暂、不长期储存。

**DM-11** 私信附件按敏感媒体逐请求鉴权，当前合法参与者须同时拥有该条消息的访问资格；本人单条删除后不能借附件 URL、历史分页、重连或其他正常入口重新访问。具体举报证据只供案件授权审核人员按最小范围读取，不能恢复删除方的普通访问资格。发送者注销后的身份脱敏、接收方保留与期限均遵循第 16 节；后台没有任意浏览全部私信的入口。

模型可替换不等于自动把数据传往另一家服务商。发生故障或高成本保护时，只有已告知且批准的处理范围内才能调整；不能未经明确政策自动转发给另一家第三方。

### 12.2 内容能否进入 AI

| 内容 | 泛社区问答 / 热门 / 自动推荐 | 主动选中分析 |
|---|---|---|
| 已发布、有效公开帖子 | 对应 AI 用途许可、当前阅读权限及过滤规则全部允许时可用 | 同样检查作者许可与当前状态 |
| 关注者可见帖子 | 不进入广泛社区总结、热门回答或面向多人的推荐；不无差别批量传输 | 用户主动选择且当前有权、作者允许相应用途、发送前知晓必要正文会给已批准模型时可用 |
| 仅自己可见帖子 | 不进入公共 AI 检索库 | 仅所有者主动选择并确认分析；继续检查本人作者设置 |
| 私人草稿 | 不自动检索，不自动加入上下文 | 仅本人主动选择自己的草稿，明确告知并确认必要处理 |
| 私信、举报证据、管理员记录 | 不作普通社区问答来源 | 首版没有通用选取入口；不能以“主动提问”取得系统任意读取权限 |
| 待审核 / 限制展示 / 已删除内容、旧版本 | 不经普通 AI 暴露 | 作者管理和治理资格不等于 AI 分析许可；首版不借此绕过限制 |
| 未能识别来源的手动粘贴文字 | 视为用户主动提交输入，不授予原帖访问权 | 发送前告知第三方处理；无法保证识别全部原作者、完整来源链和逐项设置 |

**AI-08** 对内部链接、可识别社区引用和已明确关联原帖的内容，必须执行原帖权限与作者设置；不能将已经识别的受限内容改称“手动粘贴”后绕过。对无法识别来源的输入，不主动扩展读取受限原帖、相关附件或私人信息。

**AI-09** 只发送完成当前请求所需的最小正文与来源信息，不附带手机号、认证凭据、无关个人资料或整库数据。第三方 AI 推理处理、日志与存储默认限定中国大陆境内，未经单独批准不能跨境传输；服务商必须明确承诺不将社区内容、用户输入及相关数据用于模型训练，并提供处理位置、保留期限、训练用途、删除能力及相关分包商的数据处理条款。具体供应商、模型与合同在接入前核验，不满足条件不能处理社区用户数据。后台只可切换已经批准且符合当前政策的服务商 / 模型，不能借配置变更自动向未经批准的境外服务商发送数据。公开、受限、私人草稿及其他数据继续按本节资格、最小必要与告知执行；列出数据政策不新增私信 / 证据的通用 AI 读取入口。

### 12.3 账户与逐帖设置

**AI-10** 账户分别控制 AI 检索、AI 总结、AI 推荐；单帖可进一步关闭其中某项。有效许可取账户设置与逐帖限制的交集；账户关闭时单帖不能重新开启。公开内容按明确告知的社区 AI 规则默认可以参与，默认文案与同意呈现须确认，不把公开等同于已同意一切第三方处理。

**AI-11** 按实际用途执行对应许可。允许检索而禁止总结时，可以返回合规检索链接，不能借“搜索回答”生成该帖摘要；一个流程实际包含检索、总结或推荐多个用途时，应满足所涉及的全部许可，不能更换功能名称绕过限制。用途对应的具体实现与评估用例须在规格中细化。

**AI-12** 关闭某项用途适用于该账号 / 帖子的后续调用和受影响历史，停止对应上下文构建、索引和缓存使用。普通关键词搜索与社区阅读继续按原可见性运行。重新开启后重新核验内容当前有效性和用途资格，逐步恢复索引，不复活已删除或被其他规则限制的内容。

### 12.4 历史回答撤回与继续对话

**AI-13** 回答须保留足以执行撤权的来源关联，包括直接内容与依赖此前回答引入的来源。原帖删除、失去阅读资格、被拉黑、审核限制或作者撤回有关 AI 用途后，相关原文、摘要、引用和实质依赖它的回答停止展示及继续作为上下文使用。

**AI-14** 有可靠来源追踪时，可重新生成不依赖撤回来源的回答；不能可靠区分受影响部分时，隐藏整条受影响回答并标记不可用。不能只移除来源链接仍保留原回答，也不能让下一轮从隐藏回答“记忆”中重述。未受影响的本人输入与合法回答可保留。

**AI-15** 打开历史、复制、继续提问、重试和来源跳转都执行当前校验；权限变化事件用于及时刷新，但安全不能仅依赖事件成功送达。离线不能展示无法重新核验的受限内容及依赖它的回答。已看过、截图、复制到系统外的回答以及系统无法控制的第三方副本无法保证收回。

### 12.5 会话管理、额度与恢复

**AI-16** 支持新建、查看历史、打开旧会话、自动简短标题、修改标题、删除会话、停止生成、复制合法回答、失败重试及基本反馈。历史与标题仅本人可访问；删除立即从 UI 和正常检索移除，物理清理见第 16 节。会话标题也不能保留已失权内容的敏感摘要。

**AI-17** 保存请求状态并区分提交中、检索中、生成中、已完成、已停止、失败和结果待确认。超时 / 断网保留输入和已合法保存历史，不把半截回答标成完成；重试沿用可追踪请求关联，避免重复气泡、重复额度和重复计费账目。服务商是否已收费无法确定时记录并对账，不直接判为免费失败。

**AI-18** 封闭内测免费使用 AI；已确认默认每用户每日最多 20 次成功完成请求，最大输入 8,000 Token（含检索上下文）、最大输出 2,000 Token。每日额度按后台可配置时区重置；额度、Token 上限、模型参数及合理范围内的授权用户组 / 不同 AI 功能限制统一配置。明确失败且未成功完成的请求不重复扣额度；结果不确定记录状态并对账，服务商实际成本独立记录，停止生成可能已发生的成本不能抹除。默认额度已获产品确认，实际模型兼容与费用仍须验证。

**AI-19** 支持单用户请求 / 成本保护、单次预算、全局每日预算、预算告警和高成本调用保护，由获授权管理员通过统一配置中心管理。并发请求不能突破额度或多次扣同一成功请求。用户额度耗尽、模型限流或全局预算保护时明确说明限制及可知恢复时间，保留输入；全局保护可以暂停新 AI 请求，不能跳过授权或转给未经批准的服务商；可展示普通授权搜索作为恢复入口。具体成本金额仍未给定。

**AI-20** AI 故障不阻断普通社区浏览、发布、互动和私信。后台通过统一配置中心管理已批准服务商 / 模型 / 推理区域 / 保留和日志策略、MCP 工具启停、超时、重试及成本参数，提供错误、延迟、Token 和实际 / 待对账成本统计；工具配置不能扩大只读能力或用户资格。原始对话访问需另行授权与审计，不因 AI 运维角色默认开放。

## 14. 治理、处罚、申诉与后台

来源：S03、S04、S05、S07、S08、S14。

### 14.1 内容审核与举报

**GOV-01** 基础发布检查与发布后巡检结合。通过必要检查的正常内容可发布；待进一步确认的进入待审核或限制展示。作者可查看、编辑、撤回 / 删除待审核内容及允许公开的处理说明。待审核内容不进公共信息流、搜索、热门、推荐或普通 AI。

**GOV-02** 举报帖子、评论、账号、私信；保存举报对象、理由、必要证据与提交结果。状态至少有待处理、审核中、已处理、不予处理；用户能查看允许披露的进度和反馈，不暴露举报人身份、其他人的证据或内部敏感处理信息。

**GOV-03** 举报多不等于违规。审核员基于证据可提醒、限制传播、删除内容、限制账号功能或封禁，并记录原因、操作人、时间、对象、必要依据与结果；涉及高影响自动处罚时可人工复核。紧急先限制传播也须留记录与复核。

**GOV-04** 基础垃圾内容、骚扰、重复违规、异常互动、重复发布与协同刷量防护。可配置限流与风险阈值，但不能跳过授权或用运营伪造计数。举报提交与受理故障分别展示，避免提交失败却显示已受理。

### 14.2 处罚与恢复

| 处罚类型 | 新操作 | 既有合法内容 | 用户与治理入口 |
|---|---|---|---|
| 功能限制 | 仅停止决定中列明的功能 | 原则继续展示；独立内容处置仍生效 | 显示原因、受限功能、开始 / 结束时间和申诉 |
| 临时封禁 | 指定期间禁止发布和互动 | 原则可以合法阅读，但从推荐 / 热门暂移除 | 受限入口可读处罚、期限与申诉状态 |
| 永久封禁 | 禁止发布和互动 | 从正常信息流 / 搜索 / 推荐移除；主页 / 直接链接为适当占位 | 保留必要处罚说明、申诉及独立证据授权 |

**GOV-05** 账号处罚、单条内容处置和用户主动删除分别记录；一次账号处罚不能证明所有帖子违规，也不自动永久删除所有文件。到期或撤销只恢复该处罚实际影响、尚有效的状态，再检查当前权限、拉黑、原帖、审核和媒体依赖。

**GOV-06** 不恢复用户主动删除内容、已过期请求或主动取消的关注，不自动解除拉黑；申诉恢复不是全部关系回滚。记录恢复决定和执行结果，有失败重试，避免显示账号已恢复而对应资源错误暴露或长期被错误隐藏。

**GOV-07** 受影响用户可提交理由与必要材料并查看申诉状态。不同于原处置人的有权人员最终复核，原处置人可补充说明但不能独自决定。没有第二名合格复核者时进入待复核，不以自审代替；审核人只访问该案所需证据。

| 必要受控 AI 原始调试输入输出 | 明确启用、敏感字段限制、独立访问审计 | 最长 7 天 |
| 举报证据 | 仅具体案件授权使用，不进普通业务 / AI / 搜索 | 结案后 180 天，有理由 / 授权才可延期 |

| OTP / 认证安全日志 | 最小反滥用记录，不记录可使用验证码或秘密 | 30 天 |

**DATA-01** 业务数据库、Storage、派生媒体、AI 会话、全文 / 向量索引、缓存、日志与备份分别有清理责任和可查状态。各类默认保留时间、触发条件、过期与例外策略由后台独立配置，日志与证据分别配置清理、访问和延期规则。删除 / 匿名化失败可追踪重试，不能只从 UI 消失就声称数据全部删除；调整配置不能让已经删除的内容自动公开或恢复已撤销访问。

**DATA-02** 依法或为有效争议确需保留的最小证据独立授权、明确理由 / 期限 / 责任人，不以审计为由无限保留所有个人信息。确需延长日志或证据保留须有明确理由、授权与审计；原始 AI 输入输出不默认长期记录，访问受控且避免不必要个人信息。异常延期、恢复与清理形成审计；普通日志配置不能关闭必要安全审计或绕过适用的数据保护要求，保留副本不能重新接回普通业务输出。

**DATA-03** 同一资源兼具恢复目的、案件证据或多个会话参与者的合法保留需求时，按各自授权分别管理。私信单条删除立即撤销本人的消息 / 附件正常访问；另一方仍有权访问时继续保留必要共享数据，不因一方操作直接物理删除。待双方均不再需要、保留期限届满或其他适用条件满足后清理，独立证据按 DATA-02 管理；保留记录、会话重现及备份恢复不能恢复已撤销的本人访问。

**DATA-04** 备份恢复后，先重放删除 / 撤权 / 处罚及有效隐私设置，再开放业务读取；验证备份不会复活注销账号、被删内容或已撤回 AI 来源。RPO / RTO、备份周期和可行轮转期限由部署方案提出，产品确认后验收。

新增插件同样登记业务数据、Storage、索引、缓存、日志及备份的生命周期和责任。停用 / 卸载 / 升级分别处理代码、配置、数据库结构和业务数据，共享内容、恢复副本与证据不能因卸载被直接误删；所涉授权继续按本节和 PLG-03–05 执行。默认保留 / 再安装体验待 Q-17，不由插件包任意决定。

**NTF-04** 消息持久化与推送通道独立，区分业务保存、服务商接受、设备送达、实际已读；失败重试可追踪，避免重复提醒。实时事件也不向无权订阅者暴露受限正文、名单或私信元数据。

### 24.1 核心、官方业务与第三方扩展

**PLT-01** 平台提供正式且维护的扩展契约，使开发者可独立增加 App、服务端及管理后台业务，无需为每个扩展直接修改核心源码或复制整套项目。平台公开哪些扩展已支持、哪些需要平台新增接口或原生构建；不能以未经维护的内部函数或任意核心代码补丁当插件 API。

**PLT-02** 核心与业务的边界须形成可查清单，区分不可轻易卸载的统一身份 / 认证、授权和安全、数据隔离、统一配置、插件管理及生命周期能力，与可独立交付的业务模块。尽可能让社交、校园认证、社团、活动、兴趣小组、话题、工具及 AI 扩展通过插件增加；不为追求插件化关闭基础保护。具体分类和官方社交模块是否可停用属 Q-13 / D-07 待确认。

**PLT-03** 核心平台、内置官方模块 / 插件、第三方插件分别标明来源、维护者、版本、权限和依赖。官方社交封装继续完成现有账号、帖子 / 评论 / 串、关系、互动 / 投票、发现、私信、AI、分享、治理等已确认首版规则；不能因尚无插件作者或业务分包而缺失原功能。第三方插件也使用正式契约和声明权限，不默认继承官方信任或数据库高权限。

**PLT-04** 插件对共享身份、内容、关系、媒体、通知、AI/MCP 和治理的操作须经过当前业务授权与原模块允许的接口，不能仅隐藏按钮、直接读取他插件数据或持高权限凭据绕过限制。拉黑、可见性、作者 AI 用途、治理限制、删除 / 撤权和数据区域政策跨插件持续有效；已批准工具不因作为插件安装而突破只读 AI 边界。

**PLT-05** 每个插件可调整参数注册到统一配置中心，纳入权限、环境、作用范围、依赖、版本、生效、审计和回滚；不能另建覆盖核心权限的私有配置体系。插件启用、版本兼容、依赖、入口、功能开关、权限声明、测试配置和发布策略可受控管理。多社区层级及作用对象待 Q-18 明确，不能在确认前擅自更改全局社交关系或内容资格。

|---|---|---|
| 已实现运行时配置 | 按第 19 节版本 / 生效规则更新，尽可能免构建部署 | 配置消费者、缓存与兼容性，不能凭配置产生新代码 |
| 后端 / 后台插件代码与结构 | 执行测试、依赖 / 权限 / 迁移校验及适用部署 | 自部署环境、后台发布、迁移 / 恢复及前端契约 |
| 兼容的移动前端更新 | 符合已安装原生运行环境和平台 / 渠道条件时，通过适用 OTA 流程提供 | Expo UI / Expo 更新机制、运行版本、签名 / 渠道及商店规则，尚未验证具体实现 |
| 新原生能力或不兼容变更 | 触发适用 App 重建和渠道发布 / 更新提示，未兼容用户受控处理 | 原生依赖、构建配置、版本 / 商店审核和安装更新路径 |

**UPD-03** 平台识别客户端版本与原生能力、后端契约及插件兼容条件；不兼容客户端不接收不能运行的扩展代码或可执行入口，给出明确更新 / 暂不可用提示。是否允许继续使用旧版核心、必须更新或按用户范围开放，待 Q-15；不能承诺所有插件都免重建 App。

**UPD-04** 发布支持适用环境与灰度范围、版本状态、健康观察、失败中止与恢复；测试不通过、依赖不满足、未经审批权限或不兼容不能被自动步骤跳过。灰度旧 / 新客户端并存时，数据与接口继续授权且兼容，回滚不复活已删除内容、已撤销访问或未授权插件能力。

**UPD-05** 自动流程对失败可重试、恢复和查明最终状态，避免重复安装、迁移、通知或发布；已运行旧版在安全且兼容时继续可用。不能回滚的步骤、部分成功、在途任务及外部渠道待处理状态向管理员明确，恢复策略按代码、配置、结构和数据分别记录；用户不被困在无反馈的半启用状态。

### 24.5 正式插件开发者文档与工具

**DEV-01** 开发者文档属于正式产品交付，覆盖从零创建到调试、测试、打包、部署、更新、卸载和故障排查的完整路径，使具备对应技术能力的开发者能按标准扩展各端而不修改核心源码。文档包含规范、目录结构、清单、SDK、公共类型、插槽 / API、事件、数据库迁移 / RLS、权限、依赖、兼容、配置、日志及数据生命周期，不以简单 README 代替。

**DEV-02** 提供官方开发模板、示例插件、插件生成工具、SDK / 公共类型和 API 文档；说明各工具支持的平台版本、生成内容、所需环境和限制。示例应覆盖前端页面 / 后台入口 / 后端业务及权限测试的完整关联；样例业务与数量待 Q-16，不擅自把校园认证等示例当生产功能。

**DEV-03** 文档与平台、SDK、插槽和插件版本共同维护，提供兼容表、变更 / 弃用说明与迁移指导。开发者可辨别文档对应哪一版本，接口更改有更新记录；不要求靠猜内部实现处理不兼容。正式支持窗口和公开开发者准入范围待 Q-14 / Q-16。

**DEV-04** 文档提供开发 / 测试环境创建、前端预览、测试账号 / 数据、权限声明 / 模拟、日志定位、故障模拟、自动化测试及发布回滚实践；明确可用接口与安全边界。插件开发者使用文档、模板、SDK 与测试工具完成一个跨端样例的验证作为交付证据，不把仅展示文档导航视为验收完成。

### 24.6 前后端独立调试与服务端隔离

**TST-01** 正式区分开发、测试和生产环境，服务端按真实环境隔离数据库、Storage、账号、凭据、日志及访问；不能只隐藏插件入口充当隔离。提供独立测试数据能力，不默认复制未经处理的生产私信、草稿或用户信息；隔离实例或其他机制、资源供给及费用留给方案和 Q-16。

**TST-02** 开发者可独立预览和调试 App 页面、后台扩展、后端 API、数据库逻辑、RLS 与权限及完整业务流程，使用测试账号 / 模拟数据、请求与运行日志、权限模拟和故障模拟。单端测试与集成测试分别可用，不要求影响现有生产插件才能定位新插件问题。

**TST-03** 调试账号 / 令牌与权限限定所属环境和插件范围；测试流程默认不修改生产数据、不发真实私信 / 推送、不影响真实用户。短信、通知、AI 与其他外部副作用按明确测试通道 / 模拟策略管理，仍受费用、数据处理和工具权限约束；必要真实外部集成测试的准入条件待 Q-16，不能由插件自行切换生产凭据。

**TST-04** 测试 / 预发布可验证安装、启停、升级、卸载、权限变更、依赖冲突、迁移失败、事件 / 任务重试、前后兼容、资源异常、回滚与数据保留；保留版本、配置和结果关联，测试环境故障不破坏生产及其他环境。生产发布消费已批准的同一版本产物与证据，不能检查一个包后换另一个包上线；具体证据机制留给设计。

### 24.7 与既有业务的共同约束

| 既有需求域 | 插件接入后的有效要求 |
|---|---|
