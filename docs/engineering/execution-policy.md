## 日常推进

所有前端页面先在 `docs/design/prototype/index.html` 统一入口制作原型，沿用 UI-SPEC、token、
现有原型的导航、主题及组件风格；用户明确验收该版原型后，才开发或调整对应生产页面。
未通过只继续修改原型。原型可运行、测试或代理审查不代用户验收；HTML 原型不改变移动生产端
Expo／React Native／Expo UI 路线，不采用先做移动网站再转 App 的方案。

环境足以运行和测试当前功能后直接实施。按可用业务切片组织工作，不等待完整公共基础设施验收。
先识别当前功能直接依赖；只有相关环境不可用或安全／数据边界未知才暂停其依赖部分。
媒体、完整恢复、其他端组件等在实际消费者需要时提前补齐，不能删安全义务，也不把无关工程完善当统一前置。

日常执行目标用例和直接受影响回归；类型、lint、构建、集成及端到端范围随实际变更与风险确定。
是否逐行为 TDD 由执行者判断；关键权限、安全、数据完整性及缺陷修复必须有有效测试。
批次完成以实际功能运行、对应测试与必要审查为依据，编译成功不能独自证明功能完成。
测试失败、未执行与环境故障如实记录，不伪造通过，不删有价值测试，不为补历史红链重做正常代码。

Actions 按可用业务切片批量、按需复验和发布；等待云端时继续不受影响的本地开发。

不在每次编辑／提交前要求云端、不强制完整矩阵、不把历史红链、准入收据、重复报告校验或归档回读作为日常门禁。
保留现有诊断和历史记录供需要时使用，不新增认证平台。基础工具问题集中修一次，不反复补同类台账。
