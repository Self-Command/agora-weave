# 当前快速开发与人工验收方式

2026-10-18用户明确授权：App、后端、后台三端按现有产品文档和契约继续开发；优先尽快交齐当前首版各页面，App与后台保持热更新。完整项目流程在当前首版功能齐备后集中执行，日常不反复全量联调。

本轮仅把需求落实为规范，不启动业务开发、不初始化账号、不派开发agent。用户将另开新窗口开始开发；以下均为下一开发窗口的执行要求。

## 用户负责的验收

App与后台的UI、交互、前端业务逻辑由用户在实际客户端人工复检，禁止日常独立UI检查和前端功能巡检；UI角色仅用户反馈明确涉及样式/布局问题时按需启动。现有批准与原型保留，先复用原型、token和官方组件；缺失页面按已定规则直接实现，交用户看实际效果，不再逐页等待开发前原型批准。尚未获人工验收的页面明确记待验收；不补造历史批准。

App 和后台 UI 开发必须先做共享层、再做页面：开始页面实现前先盘点现有组件与样式，把需要的共同框架、控件、状态和图标收敛到各端共享层；页面只组合复用，业务特有内容留在页面。不得复制页面级组件形成第二套实现，也不得以“以后再抽取”跳过此步骤。后台共享层以完整 Kiranism/shadcn 为基础扩展，App 共享层复用现有 Expo/React Native 组件及统一 token。修复用户反馈涉及多个页面时，先改共享层，再检查所有消费者；单页特例也要使用共享基础件。

反馈文件固定为仓库根 `人工验收.md`。主控每轮开发前读取，并在新增可测页面后追加入口、操作与预期；用户填写反馈和复查结论。保留用户原文，不覆盖其输入，不以沉默视为通过。修复用户指出的UI/交互问题后登记待复查，用户空闲时自行复查；不阻塞其他开发。

不因AI自主视觉巡检反复微调或重做已交页面。实现新功能、消除编译/运行阻断和修复必要后端安全/数据错误继续属于开发职责，不能把明显无法启动或必然破坏数据的错误交给用户兜底。

## 日常检查与最终流程

- 合并可运行增量时做受影响端的类型/构建或编译检查；契约变更后生成并检查类型。不是每改一行就全量运行。
- 后端保留必要的权限、幂等、事务、并发和数据完整性验证，优先复用现有有效测试，按变更风险最小运行。
- 不为普通前端改动新增重复组件、交互、截图或设备测试，不删除已有有效测试；仅用户反馈样式/布局时可安排定向UI检查，平时禁止工作。
- Specmatic、全链集成、设备/完整业务回归在对应功能就绪后的最终流程集中运行；高风险后端增量可提前定向校验。
- 人工结果、实际检查、未运行与待联调分别记载；开发完成不等验收通过，最终未完成项不得改成通过。

后台使用独立dev账号，官方Auth及现有MFA保持有效；凭据仅存仓库外H盘私密文件。源码仍在当前工作树；唯一H盘运行副本由主控串行同步，触发Metro/Next热更新。JS/TS/样式不重建安装包，原生变化才使用Actions构建。

7. 当前首版所有计划交付功能实现后，再组织完整真实流程、已有回归与最终验收。平时不反复跑完整链、不用mock/编译冒充完成。

## 持续开发

主控负责契约、依赖、迁移号、集成与资源；App、后端、后台三个开发agent及用户授权的辅助后端agent按独占文件开发，显式 `gpt-6-sol/high`；必要代码复检同用 `gpt-6-sol/high`，禁止继承旧gpt-6.1-sol开发配置。不预留日常UI名额；仅用户明确报告样式/布局问题时启动 `gpt-5.6-luna/xhigh` 检查对应页面/状态，平时禁止工作，不能自查全站。必要独立后端安全审查按风险启动。按当前首版范围推进，后置产品义务不自动扩大成当前页面任务。没有用户反馈时继续下一功能，不等待人工验收，不反复询问是否继续。
