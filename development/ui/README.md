设计源保留在[UI-SPEC](../../docs/design/UI-SPEC.md)、[design-tokens](../../docs/design/design-tokens.json)、[page-registry](../../docs/design/page-registry.json)及[统一HTML原型](../../docs/design/prototype/index.html)，原文件不重画、不复制成另一份原型。本文解释当前授权边界；精确页面/状态/版本快照见[pages](pages.md)。历史UI-SPEC中云端视觉矩阵和旧生成器语句已被现行用户决定取代：视觉在本地单主题独立复检，Actions保真实功能/原生/构建，不恢复旧流程。

## 当前人工验收方式

2026-10-18用户最新决定优先三端快速开发：App、后台直接按现有产品规则与原型实现缺失页面，通过Metro/Next热更新给用户查看，不再逐页等待开发前原型批准。用户负责UI、交互与前端逻辑验收，在根人工验收.md填写反馈；没有反馈继续开发，修复后登记待用户复查，不自行写通过。

UI角色固定gpt-5.6-luna/xhigh，仅用户明确报告样式或布局问题时检查对应页面/状态，平时禁止工作；不自查全站、不查功能逻辑、不重复主题矩阵。开发角色统一gpt-6-sol/high。分享Web仍属后置，原批准边界保留。

## 来源与实现

已有原型、token和批准记录保持原样；App优先复用对应页面与组件，缺失页面按既定规则直接开发后由用户验收，不补造历史批准。后台完整复用Kiranism固定快照的布局、导航、主题、表格与表单，模板身份不授产品权限。原型计数、假权限、虚构徽章/系统栏不成为产品事实。

App保持Expo/RN/Expo UI与现有Uniwind/Tailwind，必要原生props/modifier/动态style可用，不改为WebView。系统字体、安全区、键盘、触控及无障碍适配保持既定目标；不能隐藏系统栏或缩小全局字体掩盖问题。主题保持本机设置，不新增账号同步。

布局、文案、颜色等用户问题仅在收到反馈后定向检查和修复；实现自身编译/运行阻断仍处理。最终完整原生/业务验证按[验收](../acceptance.md)集中执行；截图、mock及编译不代人的验收或真实对接。
