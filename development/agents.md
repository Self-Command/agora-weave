# 多 agent 协作

共享业务决定、冻结接口、三端独立实现；辅助后端按独占文件并行补首版业务。主控先读现状再派发，开发者不另画架构或补另一套API。

| 角色 | 显式模型 / 推理 | 所有权 |
| --- | --- | --- |
| 主控 | 当前主会话 | 范围、共享契约、架构、依赖、复杂授权/事务/并发、资源交接与交付 |
| App开发 | `gpt-6-sol` / `high` | 复用原型快速完成首版页面、原生控件、controller、API适配；使用生成类型，用户验收 |
| 后端开发 | `gpt-6-sol` / `high` | 指定模块、官方扩展点、追加迁移；遵守API和当前授权 |
| 辅助后端开发 | `gpt-6-sol` / `high` | 用户于2026-10-18授权；领取与后端开发互不重叠的首版业务文件，按冻结契约实现；共享契约、迁移编号及DB操作交主控 |
| 后台开发 | `gpt-6-sol` / `high` | 完整Kiranism界面和BFF，不自造设计系统 |
| 必要后端独立复检 | `gpt-6-sol` / `high` | 按安全/数据风险定向启动，不作为每批固定角色 |
| App/后台人工复检 | 用户 | UI、交互、前端逻辑；在根人工验收.md填写问题及复查结果 |
| 反馈后UI定向检查 | `gpt-5.6-luna` / `xhigh` | 仅用户明确报告样式/布局问题后检查对应页面/状态；平时禁止运行，不查功能逻辑或扩大范围 |

允许名单只有 `gpt-6.1-sol`、`gpt-6-sol`、`gpt-5.6-luna`，禁止Astra及其他型号。
启动/恢复先核工具参数；工具未返回实际部署型号时如实记“实际型号未暴露”，不以模型自称代替核验。
固定配置不可用报告，不静默替换。优先复用同职责且配置已核的实例；长上下文、必要并行或独立审查才新建。

## 最小工作包

每次传仓库绝对路径、本入口、功能文件、契约版本/operationId、现有原型/标准与人工验收入口、已有实现位置、独占文件、依赖、目标检查和停止条件。
这是一次明确的派发消息，不另建285项任务表或执行平台。

App/后台 UI 工作包必须列明拟复用或先扩展的共享层位置，并按“盘点现有基础件 → 建立/扩展共享层 → 页面复用 → 检查重复实现”的顺序执行。页面级复制组件、图标映射和公共样式不可作为完成结果；主控验收增量时先检查共享层与各消费者。后台不得因此替换 Kiranism/shadcn，App 不另造与现有设计 token 并行的样式系统。

先查已有实现。缺字段/规则时精确报告动作与缺项，只暂停该依赖，继续独立工作。
共享契约、锁文件、配置定义、迁移编号、原型及批准由主控协调单写；契约变更核对PRD/功能后再生成，通知各端。
开发者不得为通过自己的实现改共同约定。工具检查发现类型/结构偏离，不提供文件权限隔离或证明人的同意；最终变更由独立复检核对。

## 并行与资源

按独立文件划分，主控加App、后端、后台及辅助后端四位开发者；契约齐备时并行开发，不预留UI复检名额。工具并行槽不足时优先复用或等待现有角色，不抢共享DB、运行副本和设备。
不每轮启动全部角色，不递归扩张。工作树不能隔离DB、运行副本和设备。

Prism/独立构建可分别运行；真实DB、迁移、H盘运行区、Metro、设备、浏览器交一位持有者串行使用，明确释放时机。
等待外部依赖时继续独立实现，不轮询无变化状态。

## 返回与复检

返回修改文件、实际命令/结果、剩余项和具体冲突，不把静态通过当功能通过。
按[当前交付方式](delivery-mode.md)，前端/UI只交用户人工复检；主控每轮先读人工验收.md，追加可测入口，保用户反馈，修复后登记待复查。没有反馈继续向下开发。
后端保必要有效检查，受影响端合并时做编译/类型检查；最终完整流程集中跑。不每批安排独立代码/文档/UI复检；仅用户反馈样式/布局时按需启动UI角色。
