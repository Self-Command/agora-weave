# 多 agent 协作

共享业务决定、冻结接口、三个独立实现。主控先读现状再派发，开发者不另画架构或补另一套API。

| 角色 | 显式模型 / 推理 | 所有权 |
| --- | --- | --- |
| 主控 | 当前主会话 | 范围、共享契约、架构、依赖、复杂授权/事务/并发、资源交接与交付 |
| App开发 | `gpt-6.1-sol` / `high` | 获批页面、原生控件、controller、API适配；使用生成类型 |
| 后端开发 | `gpt-6.1-sol` / `high` | 指定模块、官方扩展点、追加迁移；遵守API和当前授权 |
| 后台开发 | `gpt-6.1-sol` / `high` | 完整Kiranism界面和BFF，不自造设计系统 |
| 独立代码/契约/文档复检 | `gpt-6.1-sol` / `high` | 只读检查他人变更、遗漏、结果和保留义务，不审自己 |
| 独立UI复检 | `gpt-5.6-luna` / `xhigh` | 实际客户端单主题布局与样式；不开发、不查业务交互、不自授批准 |

允许名单只有 `gpt-6.1-sol`、`gpt-6-sol`、`gpt-5.6-luna`，禁止Astra及其他型号。
启动/恢复先核工具参数；工具未返回实际部署型号时如实记“实际型号未暴露”，不以模型自称代替核验。
固定配置不可用报告，不静默替换。优先复用同职责且配置已核的实例；长上下文、必要并行或独立审查才新建。

## 最小工作包

每次传仓库绝对路径、本入口、功能文件、契约版本/operationId、原型批准、已有实现位置、独占文件、依赖、目标检查和停止条件。
这是一次明确的派发消息，不另建285项任务表或执行平台。

先查已有实现。缺字段/规则时精确报告动作与缺项，只暂停该依赖，继续独立工作。
共享契约、锁文件、配置定义、迁移编号、原型及批准由主控协调单写；契约变更核对PRD/功能后再生成，通知各端。
开发者不得为通过自己的实现改共同约定。工具检查发现类型/结构偏离，不提供文件权限隔离或证明人的同意；最终变更由独立复检核对。

## 并行与资源

按独立文件划分，通常主控加两位开发者并预留复检名额；契约齐备、文件独立且容量允许时三端可同时开发。
不每轮启动全部角色，不递归扩张。工作树不能隔离DB、运行副本和设备。

Prism/独立构建可分别运行；真实DB、迁移、H盘运行区、Metro、设备、浏览器交一位持有者串行使用，明确释放时机。
等待外部依赖时继续独立实现，不轮询无变化状态。

## 返回与复检

返回修改文件、实际命令/结果、剩余项和具体冲突，不把静态通过当功能通过。
主控核对后安排独立复检，只查本次变化与直接依赖，修复后定向复测。
纯文档与未变原型不重开UI复检；后端验证共同业务不变量，端侧只补自己的控件/交互责任，减少重复测试。
