# 开发入口

开发方式：**contract-first-v1**。2026-10-18用户明确批准以本方案取代旧规格、计划、任务与宪法体系，
保留PRD、原型、已批准设计、生产代码、有效测试和真实未完成边界。旧体系仅在Git历史及仓库外快照查证，不恢复为开发入口。

当前交付采用[快速开发与用户人工验收](delivery-mode.md)：三端开发，App/后台热更新；用户负责两端UI/交互/前端逻辑复检，取消独立UI复检。每轮先读仓库根`人工验收.md`；不等待人工反馈，按首版范围持续推进。

## 材料权威

| 决定 | 唯一权威 | 使用方式 |
| --- | --- | --- |
| 产品做什么、哪些后置 | [PRD](../docs/product/PRD.md)、[范围决定](decisions.md) | 确认本次范围，不凭实现缩减完整产品 |
| 业务动作和失败结果 | [功能说明](coverage.md) | 读对应功能及明确引用的公共规则 |
| 请求、响应、错误、类型 | [OpenAPI](contracts/README.md) | 三端同版，类型从此生成，不维护第二套 |
| 数据库实际结构 | `supabase/migrations/*.sql` | 已应用迁移不修改；[数据字典](database/README.md)解释约束 |
| 页面外观、状态及批准 | [UI规格](../docs/design/UI-SPEC.md)、[页面登记](../docs/design/page-registry.json)、原型 | 对应具体页/状态/版本；后台以完整Kiranism源码为准 |
| 实现边界 | [架构](architecture.md)、[技术栈](technology.md) | 实现产品业务，复用完整官方基础能力 |
| 当前成果 | [status](status.md) | 历史证据不推导当前运行通过 |

不一致时定位具体动作/字段并修正其权威来源，不能在客户端增加私有约定掩盖差异。
普通实现及契约纠错由主控在已批准产品范围内处理；产品、安全、隐私、费用和具体生产操作变化仍由用户决定。

## 独立开发

功能的业务判断、页面状态与OpenAPI确定后，App、后端、后台可同时或分别开发。
App/后台用生成类型与Prism；后端按同版契约及数据库规则实现，由Specmatic检查真实接口。
独立指各自构建、运行和校验，不表示三端各自决定字段或取消最终真实对接。

1. 主控核对现有源码、原型批准、范围和依赖，只派缺失增量。
2. 开发者领取功能说明、只读契约版本、现有实现位置、独占文件、指定验证与依赖。
3. 端侧开发不自行改共享契约、迁移编号、依赖或原型。缺项精确交主控，不猜产品规则。
4. 公共契约由主控单写，审查影响后再生成类型，各端一起切换版本。
5. 日常按[最小检查](acceptance.md)保持可运行，用户人工验收App/后台；首版功能齐备后集中跑完整流程。

角色、模型与资源交接见 [agents](agents.md)。不另建任务平台、认证收据或自定义规格执行器。

## 成果保护

现有生产源码和有效测试优先复用，不为迁文档重做功能。原型HTML/JS/CSS、tokens、图片、页面批准登记保持原字节；
本次不授新页面批准。既有未提交成果同样保留。快照与最终逐文件核对见 [迁移记录](migration.md)。
业务文件中的 `*.spec.ts` 是测试，不属于删除的旧规格体系。
