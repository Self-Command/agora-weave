# 开发检查与人工验收

用户2026-10-18明确采用[快速开发方式](delivery-mode.md)：App、后台的UI、交互与前端逻辑由用户人工复检，日常尽量少测，完整流程在当前首版功能齐备后集中执行。

| 时机 | 执行内容 | 负责人 |
| --- | --- | --- |
| 合并可运行增量 | 对应端编译/类型检查；契约变更后api:generate及api:check | 开发与主控 |
| 高风险后端变更 | 当前权限/撤权、幂等、CAS、事务/并发、数据完整性必要有效验证；复用现有测试 | 后端，必要时独立审查 |
| 用户空闲 | 实际App与后台UI、点击交互、前端逻辑及自主联调 | 用户在根人工验收.md反馈 |
| 用户报告问题后 | 修复指定问题，更新处理说明及待复查；样式/布局问题可触发定向UI检查，不阻塞其他开发 | 对应开发，必要UI角色，用户复查 |
| 当前首版功能齐备 | Specmatic真实接口、核心真实链路、适用业务与原生/设备回归集中执行 | 主控组织，用户验收 |

禁止日常独立UI检查，仅用户明确报告样式/布局问题后允许UI角色检查对应页面/状态，不主动开展前端视觉/交互巡检，不为普通前端增量新增重复组件/设备/截图测试，不强制逐行为TDD、固定测试数量或每次全量构建。编译失败、运行阻断及后端安全/数据错误仍及时处理。

保留有价值的既有测试和结果；源码/依赖/config/输入仍适用时复用，不因流程简化删除测试。未测试、失败、跳过、环境问题和用户待验收分别记录，不能宣称通过。

openapi-typescript只生成类型；Prism只模拟协议；Specmatic检查通信契约，不能证明权限、事务或业务完成。三工具继续使用同版OpenAPI，按当前时机运行，mock不算真实联调。

真实后端检查只在隔离dev/test、必要既有夹具中执行，不能对生产或真实用户数据自动生成写请求，不reset/seed。生产发布、正式分发和资源变更继续按具体版本/范围授权。
