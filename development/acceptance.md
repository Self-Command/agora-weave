# 验收方式

接口契约减少重复手写通信测试；保留有价值的历史测试及关键业务不变量，按实际改动选验证范围。

| 层 | 必要验证 | 不能据此声称 |
| --- | --- | --- |
| 契约 | `npm run api:check`：OpenAPI、示例、生成类型一致性 | 权限/事务正确或产品完成 |
| 端侧 | 对应typecheck/build及受影响控件/原生输入导航反馈 | 模拟接口已接真实服务 |
| 接口 | `npm run api:verify -- --surface ... --base-url ...`，Specmatic检查真实隔离服务 | 未选中接口或完整业务链通过 |
| 业务 | 复用单元/API/集成测试，必要的当前权限、幂等、CAS、原子性/并发和缺陷验证 | 单次成功覆盖全部风险 |
| 对接 | 当前交付核心旅程连接真实App/BFF/后端，核失败和未知结果 | 正式短信、生产、后续产品已通过 |
| 外观 | 稳定实际客户端与已批原型/官方模板单主题整页对照 | 人类批准或点击交互正确 |

不强制逐行为TDD或固定测试数。已有结果仅在源码、依赖、配置与输入仍适用时复用。
失败、跳过、未执行、超时和环境故障分别记录，修复后窄复测；不为纯文档重跑完整设备矩阵。

openapi-typescript仅生成类型，不检查运行JSON；Prism返回模拟响应，不自动模拟完整业务状态；
Specmatic校通信契约，不自动证明复杂权限、数据副作用或事务。三者使用同版OpenAPI，各层实际结果分别保留。

真实校验默认仅已实现的只读JSON操作。变更操作显式选择隔离dev/test和现有夹具，不自动对生产/真实用户数据发生成请求。
生产发布、正式分发和资源变更仍需具体版本/范围授权，不因本方案批准自动执行。

本次完成标准：新文档覆盖原需求/未完成边界；三工具实际运行；App/后台消费生成类型；原型及非本次改动源码测试逐文件保留；
旧体系与活动引用退出；同步及相关工程检查通过；独立复检无未解决的重要问题。不把迁移完成记作285项业务完成。
